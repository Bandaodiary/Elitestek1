# Efinity/RV32 boardless smoke project

Historical C1 ABI/toolchain probe: do not use this directory as the current
R2 host/S2 Lite application. Its default `rv32imc` also assumes an extension
absent from the generated S2 core. See [the current S2 entry](../c39_s2_probe/README.md).

This directory is a deliberately small Makefile project for validating the
installed `riscv-none-elf-*` toolchain before a board-specific Sapphire BSP is
generated.  It links the existing Case-1 CSR driver against a minimal startup
file and emits an ELF, Intel HEX, binary, map, and disassembly in `build/`.

It is not the final Sapphire application: the MMIO address is a parameter,
the startup code does not initialize a generated BSP, and the loop is only a
compile/link probe.  After IP Manager generates a Soft Sapphire instance,
import this directory as an Efinix Makefile project (or copy its source list
into the generated application), replace `linker.ld`/`startup.S` with the
generated BSP startup/linker, and set `C1_ACCEL_MMIO_BASE` from the generated
`soc.h`/address map.

The Makefile keeps every object under `build/` (including the object compiled
from `../src/c1_accel.c`), so `make clean` removes all objects generated by the
current build. This housekeeping fix prevents new builds from placing
`c1_accel.o` under the old `software/src` path; a stale object from an earlier
build, if present, must be cleaned separately once.

## Build from PowerShell

```powershell
$ide = 'D:\ELS\efinity-riscv-ide-2026.1'
$env:PATH = "$ide\toolchain\bin;$ide\build_tools\bin;$env:PATH"
make -C .\case1\software\efinity_smoke clean all
```

The default flags are `-march=rv32imc -mabi=ilp32`; override `MARCH` and
`MABI` only after the generated Sapphire BSP confirms the CPU configuration.
The generated BSP, `soc.h`, linker script, and startup code must remain a
matched set.

For a generated BSP, prefer injecting its header rather than editing
`main.c`:

```powershell
make -C .\case1\software\efinity_smoke clean all `
  SOC_INCLUDE='D:\path\to\generated\bsp\include' `
  SOC_HEADER='soc.h'
```

If that header defines `IO_APB_SLAVE_0_INPUT`, the smoke source uses it as the
default `C1_ACCEL_MMIO_BASE`; an explicit `C1_ACCEL_MMIO_BASE=0x...` override
still takes precedence.  Verify the symbol against the generated address map
before running on hardware.
