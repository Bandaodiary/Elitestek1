# 面向 RISC-V SoC 的 FPGA 图像风格迁移协处理器架构设计与验证

版本日期：2026 年 9 月 15 日；技术基线：C39 one-hot。

参赛队伍、成员与指导教师：【待补充 M01】

## 摘要

面向图像采集、神经网络风格迁移与连续显示并行运行的需求，本设计采用 RISC-V 控制面与 FPGA 数据面分工，将裁剪缩放、INT8 推理、帧存储和显示读出组织为共享 DDR 的处理系统。当前 C39 组合采用明确选源的 49 个源码文件，以双 RGB 像素输入、四主 AXI128 总线和四输入三输出帧租约连接视频链路；计算端执行当前模型的 18 阶段计划，并通过虚拟上采样、局部行融合、六路输出计算和窄舍入降低搬运及逻辑开销。同边界纯 host 布局布线结果为 40,476 XLR、117 RAM、121 DSP，较 C37 净减少 842 XLR。640×480 六帧系统仿真中，五个完成间隔的最差值为 6,433,652 核心周期，按标称 150 MHz 换算为 23.314907 fps，显示无欠流。实际 Sapphire S2 与唯一 DDR 联合资源探针采用独立的 100 MHz 边界，资源为 51,900 XLR、165 RAM、125 DSP。上述证据支持当前 RTL 数值一致性、协议协作和资源优化结论；真实 CPU 软件执行、100 MHz 联合吞吐、物理视频接口、板上画质及功耗仍待验证。

关键词：FPGA；RISC-V；INT8；图像风格迁移；行融合；AXI；帧调度

## 1 赛题需求与设计目标

赛题一要求将摄像头采集、图像风格迁移、CPU 调度和视频显示组成持续运行的系统。项目采用的需求基线包括 640×480、30 帧每秒的采集目标，稳定不低于 15 帧每秒的处理目标，以及 720p60 或 1080p30 的显示适配和 FPS 叠加。多风格及参数规模要求属于进一步评价内容。采集频率、网络处理频率和显示刷新频率分别由不同环节决定：显示端可以重复读取一幅已完成画面，网络则只能在新任务实际提交后增加完成帧计数。因此，评价实时性应观察连续任务完成间隔，而不能直接采用显示接口的刷新率。

Ti60 的片上存储与逻辑资源限制决定了计算阵列不能脱离供数系统独立设计。卷积结果需要经过量化、行缓存和写回才能交给后继算子，显示读取又与推理争用 DDR；即使乘法器有空闲，窗口或总线阻塞仍会延长帧间隔。设计目标因而同时包含数值正确、帧生命周期正确和资源可实现性。当前优化保持算法、96 路乘积并行度、通道及行容量合同、AXI 并发深度不变，通过改变数据表示和选择逻辑获取实际资源收益。

本报告以 C39 已验收的 one-hot 组合作为开发基线，C37 保留作同条件比较与回退。验证分为逻辑仿真、映射与布局布线、板级运行三个层次。现有六帧结果属于含真实网络算术的系统仿真，联合探针则包含实际生成的 CPU 和 DDR 逻辑资源；二者都不构成摄像头到显示器的板上验收。将这些层次分开，可以使已取得的结果直接服务于后续集成，同时保留真实时钟、物理接口和运行软件尚需补齐的条件。

## 2 系统总体架构与软硬件分工

当前视频入口位于 ISP 之后，在摄像头时钟域每个有效拍接收两个 RGB888 像素，数据宽度为 48 位，并携带 VS、DE、有效及错误信号。光栅解析器恢复像素位置，采集入口选取 ROI，通过异步 FIFO 将被接纳的数据交给核心域。缩放器把选定区域变换为网络输入尺寸，采集写入器将 RGB 像素按 RGBx32 格式存入 DDR。网络从完成的输入帧取得任务，按生成计划处理并写回风格帧；显示端读取同一标签对应的原图和风格图，形成可重复刷新的配对画面。

双像素输入与 RGBx32 存储承担不同任务。前者适配每拍两个 RGB 像素的流接口，后者为每个像素保留四字节位置，使四个像素恰好组成一个 128 位总线拍。这里的扩展字节用于对齐，不能解释成摄像头输出四通道颜色。当前端到端回归从上述 RGB 接口进入，未穿过真实 CSI、RAW 解包和 Debayer。仓库中的早期 RAW/ISP 模块可供后续接入使用，但其独立验证结果不并入 C39 六帧回归的覆盖范围。

CPU 负责读取状态、配置视频和摄像头控制寄存器、处理错误及中断，并参与参数和帧数据的管理。高频像素搬运和网络运算由硬件自行推进，避免软件逐像素干预。APB3 桥提供控制入口及 IRQ，CPU AXI 适配器则将软件侧访存转为视频总线接受的事务子集。二者是独立通路：寄存器访问通过并不意味着 CPU 已正确执行启动代码，行为模型产生的 AXI 压力也不意味着真实处理器缓存行为已被覆盖。

当前纯 host 顶层保留外部 CPU 事务、APB、摄像头和 DDR 用户接口，用于测试和公平资源比较；Sapphire S2 联合顶层再连接实际生成的 CPU 及唯一 DDR 实例。明确的 49 源闭包选择计算、窗口、操作数解包及当前模型计划，外层资源探针另计，不应将所有历史版本同时导入。部分模块名称延续 R2 或 C37，但其实际实现由选源关系确定。判断开发基线应依据选中的源码和生成计划，不能依据目录编号或文件注释中保留的实验沿革。

## 3 图像处理与 INT8 风格迁移算法

在当前输入配置中，源光栅为 1920×1080，选取横向起点 240、纵向起点 0 的 1440×1080 区域，再缩放为 640×480。ROI 与目标同为 4∶3，裁剪承担宽高比调整，缩放承担采样密度变换。前端采样不允许依赖下游随时反压摄像头，因此需要在帧接纳、缓存容量与核心消费速度之间建立完整条件。帧错误或资源不足时，应结束该帧的所有权并恢复到明确边界，不能把不完整图像作为正常网络输入。

双线性插值对四个邻近像素分两次计算。横向权重之和为 4096，横向加权结果先加 2048 再右移 12 位；纵向使用同样的独立舍入规则。当前算术将互补权重的加权和改写为基准像素加像素差乘权重，以减少乘法需求，但仍保留横向舍入后再纵向舍入的边界。若把两级合成一次高精度乘加后再取整，结果可能不同，因而不能仅按实数双线性公式判定 RTL 等价。四级弹性流水线同时保存像素、权重和位置，在输出阻塞时维持整项数据一致。

网络使用当前训练导出的轻量学生模型，配置为两个残差块、24 通道中间扩展和解码前投影。输入 RGB 先转换为带符号八位表示，特征按八通道一组组织。前两个 3×3、步长为 2 的编码算子把空间尺寸从 640×480 依次降至 320×240 和 160×120，通道从 3 变为 12、再变为 24。较低分辨率承载残差处理，使主要通道运算发生在较小空间上；解码端再恢复空间分辨率，而不是在完整输入尺寸上维持全部 24 通道卷积。

当前生成计划有 18 个阶段，其编号对应图语义和提交状态，不等于 18 个独立卷积核。表 1 列出实际顺序，其中视图仅改变寻址解释或完成语义，不产生一次完整张量搬运。

| 阶段 | 运算 | 输出尺寸与通道 | 执行特点 |
|---|---|---|---|
| 0 | 3×3 卷积，步长 2 | 320×240×12 | RGB 输入 |
| 1 | 3×3 卷积，步长 2 | 160×120×24 | 编码 |
| 2—5 | 1×1、DW3×3、1×1、残差加 ReLU | 160×120×24 | 第一个残差块 |
| 6—9 | 1×1、DW3×3、1×1、残差加 ReLU | 160×120×24 | 第二个残差块 |
| 10 | 1×1 投影，24→16 | 160×120×16 | 解码前降通道 |
| 11 | 最近邻上采样 2 倍 | 320×240×16 | 虚拟视图 |
| 12 | DW3×3 | 320×240×16 | 虚拟上采样输入 |
| 13 | 最近邻上采样 2 倍 | 640×480×16 | 虚拟视图 |
| 14 | DW3×3 | 640×480×16 | 与阶段 15 行融合 |
| 15 | 1×1，16→8 | 640×480×8 | 消费阶段 14 的行结果 |
| 16 | 3×3，8→3 | 640×480×3 | 融合 RGB 写回 |
| 17 | 带符号八位转 RGB | 640×480×3 | 终止视图 |

执行计划由显式张量边及形状生成，同时检查算子模式、通道、空间范围、残差来源和存储容量。上采样视图只允许连接受支持的 DW 消费者；输出转换只融合到独占输出的 8→3 空间卷积。这样的限制使计划能静态确定存储生存期和参数块，也界定了可复用范围。改变网络拓扑后需要重新生成并验证计划，现有后端不是任意 CNN 的运行时解释器。24 通道、512 行字容量是当前资源探针配置，48 通道和 1024 容量的兼容测试不代表扩大配置仍占相同资源。

卷积使用 INT8 操作数和权重，归约结果及偏置形成有符号 32 位累加值，再乘每通道的有符号 18 位整数乘子。设该乘积为 p、移位为 s，当 s 大于零时，取绝对值加半个量化单位后右移，再恢复符号；s 为零时直接保留整数。该规则在半值处远离零取整，随后执行 ReLU 或限制到 −128 至 127。合法移位为 0 至 47。残差两支使用一致尺度，相加后经过 ReLU，输出层再转换回 RGB 编码；训练与导出必须共同遵守这些离散规则。

当前稳定 Mosaic 包的参数 arena 为 8,931 字节，其中包含卷积权重、偏置、乘子、移位及对齐空间。它与硬件按阶段重排的参数传输块不是同一种容量口径。训练配置记录了教师蒸馏、训练阶段使用的 SqueezeNet 1.1 特征网络、量化感知训练，以及平移和一个最低有效位噪声的一致性约束。特征网络和教师不部署到 FPGA。模型清单仍标记画质未验收，稳定性训练配置也明确不是实际视频；因此可以报告该模型已参与数值回归，但不能据此声称完成标准 CycleGAN 或 FastStyle 的整体复现。

## 4 RTL 子系统设计与模块协作

采集任务在首个有效 ROI 像素进入前取得输入帧租约，任务描述持续保持到缩放及写入器接受。缩放器输出完成只表示不再产生新像素，采集完成还必须等待已经提交的 AXI 写事务收尾。将这两个条件放在同一任务生命周期内，可以防止网络读取尚未写完的输入。取消也需要区分尚未接纳的命令、正在处理的像素和已经进入总线的写入，已对外可见的完成结果不能被稍后取消信号撤回。

网络得到输入、输出、工作区和参数区地址后，读取当前阶段计划并配置行执行器。参数加载器按照卷积类型重排权重，六路权重存储为共享计算阵列提供相应片段。阶段计算启动的前提是需要的参数和特征准备完成，而不是仅有阶段编号。首次归约拍锁定通道号、掩码、标签和残差属性，直到该批事务全部退休之前，仿射参数表保持所有权；否则前一层累加值可能错误使用后一层乘子，即使单独测试乘法器也无法发现这种交接错误。

空间供数器从分区行存储提取卷积邻域，点卷积供数器按通道向量读取，残差路径提供相同位置的两支特征。分区窗口保留同步读和双请求槽，以有限缓存接收请求并按既定时序返回窗口。当前窗口请求启动间隔为两拍，不能由计算端可逐拍接收推导窗口也达到每拍一次。跨行和边界复制由窗口与坐标合同共同处理；回压时请求元数据和已形成的操作数必须一起保持，避免窗口内容属于一个像素而输出标签属于另一个像素。

C39 将搬运中的六个完整操作数向量压缩为 432 位表示，计算入口再恢复为 768 位。点卷积保留两个像素向量，并通过通道编号回绕判断当前 lane 使用哪个向量；RGB 模式按两组三路输出选择；深度卷积每路保留九个八位样本，即 72 位；残差每路仅需两个八位值。one-hot 解包共享模式译码，以互斥掩码和并行或操作生成结果。压缩节省的是重复携带的数据和选择逻辑，未删除有效数值，也未改变模式集合中保留编码的默认行为。

计算阵列由六路输出组织，每路每拍接收 16 对八位数，共 96 路乘积。较长归约通过首次拍、结束拍及标签连续累加，六路掩码允许不足六个有效结果的尾部作业。输出先经过独立的参数解析弹性级，再进入五级量化流水线。窄舍入不再跨级保存完整宽位加偏结果，而只保存符号、商的低八位、高位非零标志和舍入保护位，再生成进位和饱和值。该表示保留最终 INT8 结果所需信息，使逻辑宽度降低而五级时序、回压行为及每拍一项的接收能力不变。

行融合针对阶段 14 的 DW16 与阶段 15 的 PW8，DW 的一行结果直接交给点卷积消费，从而避免该中间结果按完整帧落地后再读回。融合计划仍须延长空间源张量的生存期，保证 PW 写出的目标不会覆盖 DW 后续行尚需读取的数据。其他阶段按计划保留正常 DDR 读写，因此当前设计不能描述为全网络中间层均不访问 DDR。RGB 输出转换与末级空间卷积写回结合，帧完成则继续等待总线确认；从算术结束到帧可显示之间保留明确的提交屏障。

## 5 存储、总线、时钟域与帧调度

DDR 统一存放输入帧、输出帧、三个张量工作槽及参数区。工作槽按 8 MiB 间隔组织，默认 arena 基址为 0x08000000，工作区起点为基址加 0x00800000，参数区起点为基址加 0x02800000。空间预留用于固定地址合同，不表示每个槽都实际写满。640×480 的 RGBx32 帧占 1,228,800 字节，即 76,800 个 AXI128 数据拍。中间张量按 C8 分组，一行拍数为向上取整的半行像素数乘向上取整的八通道组数，剩余通道位置参与对齐而不成为有效输出。

当前帧租约管理器具有四个输入缓冲和三个风格输出缓冲。采集取得可写输入槽，网络选择最新完成输入并占用空闲输出槽，处理成功后两者一起进入可显示状态。原图与风格图以标签关联，重复显示期间继续持有同一配对；只有选定替代画面后，旧配对才释放。管理器允许回收过期但未被消费的就绪帧，不回收正在采集、计算或显示的帧。这一规则以有限帧存储维持输入新鲜度，也解释了采集次数可以多于网络处理次数，显示次数可以多于网络完成次数。

张量槽分配还必须保留残差旁路。以第一个残差块为例，编码器输出在槽 1 中保留，扩展、深度卷积和投影结果依次使用槽 0、槽 2 和槽 0，残差加法再同时读取投影结果及槽 1 的旁路。这里允许重用的是已结束生存期的旧结果，而不是当前算子的输入。对空间卷积，即使某一行已消费，后续窗口仍可能需要相邻源行；生成器因此按完整物理源的消费者关系判断释放时机。虚拟上采样沿用原张量根节点，行融合又将该根节点的占用延长到点卷积阶段，避免逻辑视图掩盖实际存储依赖。

总线实际有四个主客户端：编号 0 为 CNN 图执行读写，编号 1 为采集写入，编号 2 为显示读取，编号 3 为适配后的 CPU 访存。读写仲裁分别维护接受次序、响应路由和未完成计数，再连接唯一物理 AXI128 接口。参数和张量搬运属于 CNN 客户端内部任务，不应再当成独立主端口累计。相较逐算子独占外部端口的组织，共享图执行入口把算子切换留在计算子系统内部，总线只负责可见事务及响应归属。

CPU 适配器保存外部请求标识，在归一化总线返回后恢复原标识，并检查访问大小、突发和受支持属性。该接口服务于普通非一致性 DDR 子集，不提供通用缓存一致性、原子或独占语义。软件在把缓冲交给 DMA 前仍需建立缓存与内存可见性规则。APB 使用 16 位本地窗口偏移，高位别名应被拒绝；S2 平台将当前 host 窗口映射到 0xf8100000。摄像头统计经快照读取，以避免软件一次读取组合了不同时间的跨域计数。

ready/valid 握手决定事务是否真正转移，等待期间数据和标签必须保持。写入发出后，以响应及欠账归零作为提交依据；出现取消或错误时，停止接纳新工作与排空已接受事务是不同动作。局部计算复位可以丢弃片上部分结果，却不能凭空取消 DDR 已接受的 AXI 事务。帧租约、总线计数和流水线有效位必须在同一生命周期内协调，才能避免重启后迟到响应写入新任务上下文。

摄像头与核心之间采用异步 FIFO 和受保护快照。物理输入不能像普通内部流那样无限暂停，FIFO 满溢和帧错误必须可观测，并与取消、帧超时联动。纯 host 标称核心频率为 150 MHz，真实 S2 联合探针的核心、CPU 和 DDR 用户侧采用 100 MHz。host 默认帧分频参数为 2，而用于验收的 camera30 六帧仿真明确将其设为 1，源端不允许回压且没有跳帧。默认配置和验收配置的这一区别必须在复现时保留，避免以降低采集压力取得看似相同的吞吐结果。

## 6 仿真验证与综合资源评估

验证链从 Python 整数参考和训练导出合同开始，逐步检查算术、窗口、完整算子、图执行及采显并发。当前模型绑定不仅检查参数文件，还核对生成计划与实际编译来源，防止换了模型却仍使用旧 ROM。验证中的错误注入用于证明检查能够发现真实故障，而不是只观察正常输出出现 PASS。下述数据对应已有运行的原始输出、终态和独立复核记录。

量化原始 RTL 测试接受 9,775 项、退休 9,762 项，差额 13 项由复位丢弃解释；同时覆盖 4,702 个保持周期、7 个复位周期和 244 次连续启动间隔为一拍的检查。测试覆盖八个接口 lane 和 48 种合法移位，保护位、进位及弹性保持三类实际故障均被检出。另有覆盖 49 位幅值全域、符号、ReLU 和移位的算术表达式决策图补证，证明对象限于该表达式，不能据此声称完整 RTL 的控制和时序已获得形式证明。

操作数比较覆盖八种编码，完成 11,016 次 768 位展开结果比较和 5,632 次合法回环，其中包含 640 次点卷积回绕。窗口在 512 与 1024 深度下分别覆盖 46 和 57 种配置，总计 10,680 个请求，并与基准逐拍及独立参考一致；两组保持周期分别为 4,116 和 5,686。完整算子无回压与有回压两轮各完成 187 个作业、167,635 个向量，并覆盖六种复位模式。有回压一轮记录 192,713 个保持周期，支持当前控制在已测压力下保留数据与所有权的结论。

系统模型队列包含 Starry、Mosaic 和稳定 Mosaic 三组，其中前两组完成小尺寸矩阵验证，稳定 Mosaic 完成 640×480 六帧原生时序测试。六帧均提交 18 个阶段，末级 RGB 阶段编号为 16；共完成 9 次采集、14 次显示及 8,601,600 个正确显示像素，欠流和显示遗漏均为零。该像素统计包含重复刷新及配对显示，不能直接作为独立网络输出样本数。仿真同时存在 CPU 行为访存，读写返回与八位请求标识恢复经过检查，但未执行受保护 CPU 内部实现。

五个连续完成间隔依次为 6,316,040、6,343,354、6,433,652、6,398,800 和 6,358,814 核心周期。按最差间隔和标称 150 MHz 计算，保守观测吞吐为 23.314907 fps，最差值与 C37 相同。最差已观测采集间隔对应约 30.426556 fps，因而该结果没有通过降低源帧率掩盖处理瓶颈。这里报告的是有限六帧窗口内的仿真完成速率，不是长期稳定运行统计，也不是 100 MHz 官方 CPU 联合系统或板卡实测。

资源比较分别固定各自边界。当前纯 host 及 S2 联合工程均选择 Titanium Ti60F225 和 I3 时序模型。六有效 lane 量化探针在相同约束下由 3,706 降至 2,700 XLR，减少 1,006，约 27.1%，两者均使用 12 DSP，最终建立和保持裕量为正。纯 host 的完整 PNR 比较见表 2：C39 净减少 842 XLR，约 2.04%，RAM 和 DSP 不变。叶级收益已包含在整体实现中，不能再与整机节省相加；单独替换量化的 host MAP 曾出现面积回退，也说明综合共享和布局影响不能由局部节省线性预测。

|---|---:|---:|
| LUT4 / FF | 28,933 / 17,945 | 28,079 / 17,335 |
| 最终 XLR | 41,318 | 40,476 |
| RAM / DSP | 117 / 121 | 117 / 121 |

CPU 精简比较使用同版 Sapphire 3.4.1，固定 C37、DDR 和 100 MHz 联合边界。S0 到 S2 的 MAP 结果从 40,102 LUT4、27,161 FF、187 RAM 降为 35,738 LUT4、23,673 FF、165 RAM，分别减少 4,364 LUT4、3,488 FF 和 22 RAM，DSP 保持 125。该差值是 MAP 资源差异，不是最终 XLR 差异。采用 S2 与 C39 后，实际联合 PNR 为 51,900/60,800 XLR、165/256 RAM、125/160 DSP，逻辑利用率为 85.36%，最终 setup/hold 裕量为 +0.293/+0.026 ns。剩余容量需要留给板级接口及约束变化，不能视为整套视频 Demo 可直接加入的预算。

联合映射后定向 CDC 审计覆盖 56 个同步触发器、摄像头到核心 127 个端点、反向 14 个端点及 32 位标签，Gray 路径偏斜为 0.066/0.042 ns。工具完整 CDC 分类曾内部断言失败，现有通过结论仅针对指定 host 路径，不扩展到完整 CPU、DDR、JTAG 和复位网络。历史联合摘要还存在顶层名称截断导致的 FF 缺失、RAM 误记零问题；独立复核确认正确 MAP 数值为 35,368 LUT4、23,053 FF、165 RAM、125 DSP。比较采用修正解析的独立记录，历史失败证据仍保留。

## 7 Efinity 板级集成方案与关键问题

板级集成以实际生成的 Sapphire S2、当前 host 和唯一 DDR 用户通路为基础，避免不同演示工程各自引入一套内存控制器和时钟网络。当前联合接口已完成九项检查，并以错误 BRESP、RID 及校准门控连线验证故障能够被检出。平台合同也拒绝 CPU/DDR 时钟错误、绕过校准、冒用 150 MHz 及错误压缩指令集配置。它们约束的是接口及生成物之间的一致性；真实 DDR PHY 的初始化、训练和板级信号质量仍需实际硬件证明。

S2 使用 RV32IM，并要求当前软件工具链按 CSR 与 fence 扩展编译，不能直接继承旧 RV32IMC 软件配置。当前只读探测程序读取 host 标识、版本和状态，完整驱动另完成六个公开 API 的编译及反汇编检查。驱动链接组件包含 229 条 32 位指令、916 字节文本，六个符号保留且无未解析符号；这些结果证明软件对象与当前 BSP 合同一致，但对象本身不是可下载的完整应用。CPU 启动、异常入口、PLIC 中断处理、缓存维护以及 DMA 所有权交接需要在实际运行中闭合。

摄像头路径需要把传感器配置、CSI 接收、RAW 格式和 Bayer 相位接到当前双 RGB 输入之前。若前级每拍像素数、有效极性或行末处理不同，应通过适配层明确转换，不能仅连接相同宽度的信号。显示路径则需把现有请求驱动的 RGB 读出连接到选定视频时序及 HDMI/TMDS 物理输出，并验证刷新期间的预取和欠流处理。旧 ISP 或显示模块可以提供实现参考，但它们新增的存储、DSP、时钟和延迟必须重新计入联合边界。

从纯 host 转入真实 CPU 联合系统后，时钟和 DDR 服务条件均发生变化，不能按 150 与 100 的比例换算后直接宣布达到赛题帧率。应在真实软件配置与外设时序下记录完成帧计数、帧间隔、丢帧、欠流和总线错误，再决定是否需要进一步优化。当前核心同域路径具有正时序裕量，并不自动保证所有跨域和引脚路径满足最终板级约束；器件速度等级、PLL 输出、复位释放和时钟域例外必须绑定实际板卡工程。

## 8 设计总结与后续工作

C39 将当前 18 阶段 INT8 模型映射到共享六路计算阵列，通过明确图计划、局部行融合和帧租约把输入、计算及显示组织为可并发系统。窗口选择和操作数表示的优化保留了原有数值与容量合同，窄舍入则在不改变五级弹性流水线的前提下降低中间逻辑宽度。同边界纯 host 的实际 PNR 净减少 842 XLR，六帧仿真的最差完成间隔未退化，支持选择 one-hot 组合作为后续开发入口。

目前最接近板级集成的证据是实际 S2 CPU、C39 host 和唯一 DDR 的 100 MHz 联合资源结果，以及指定 host 跨域路径审计。其逻辑利用率已达 85.36%，后续工作的约束是保持可用资源和完整时钟合同，同时把软件、输入物理接口与显示物理接口接入。完成这些条件后，再以实际采集内容评价画质、时序稳定性、处理帧率和功耗，才能形成从算法输出到比赛系统的最终结论。
