# C39 产生端紧凑格式实验（未提升为主线）

原C39组合版MAP/PNR反而比C37多资源；这组独立源只考察压缩位置是否合适，不覆盖已经测量的C39或保留的C37。

- 空间feeder新增432位`req_packed_a`，直接输出已有的紧凑寄存器；encoder模式输出共享128位输入。
- engine直接选择紧凑的空间请求；PW/残差分别从线性feeder选择两组128位或六组16位。
- 删除engine后端通用打包器，避免空间数据先展开为768位、跨源选择、再压缩。
- 请求寄存器、mode/channel标签、解包器、MAC并行数、两槽窗口及流水级数不变。原768位空间输出保留给独立测试台及仿真断言。
- 仍沿用C39量化和窗口候选，因此不能将该实验等同于已优化完成的生产版本。

显式49源闭包及可复现生成器：`case1/golden/c39_direct_sources.py`；工程：`case1/efinity/c1_ti60_c39_host_direct.xml`。同名模块必须替换编译，不能与C39/C37 engine和空间feeder同时加入工程。

已通过原DW/PW融合短测（12宽双回压、640宽、两阶段复位、三实际故障负控），未完成187作业全算子/原生整机回归。资源结果以对应实际summary为准，不因短测通过宣称面积或吞吐收益。

`c39_host_direct_pnr_20260915a`于2026-09-15实际完成：28,373 LUT4 /17,322 FF，最终40,775 XLR /117 RAM /121 DSP；同边界C37为41,318 XLR，净少543（约1.31%）。当前纯host约束下最终setup/hold为+0.257/+0.026ns；私有工程清理。比native少310 XLR，但功能验证覆盖仍少于native，尚不能替换主线。
