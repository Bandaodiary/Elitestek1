# 三帧布局预检：不相交地址范围快捷判断

## 生产 RTL 改进

`c1_frame_triple_layout_check` 新增默认打开的 `FAST_DISJOINT_ENVELOPE`。
现有 49-bit 串行跨度检查完成后，保存三个已验证的 33-bit exclusive end。
PAIR_INIT 对每对帧先检查：`end_a <= base_b || end_b <= base_a`。
成立时整个地址范围不相交，可直接检查下一对；不成立时仍执行原有逐行
精确扫描，不能把“整体范围相交”当作“有效像素必然重叠”。

安全依据：已验证 stride >= width*4，所有有效行都在 `[base,end)` 内；
两个整体范围互不相交，其子集也不相交。快捷分支只判定安全，不新增
保守拒绝。几何、分区、溢出检查仍先于任一快捷判断；4-GiB 末端使用
33-bit 保留，避免截断成零。取消和结果背压协议不变。

新增逻辑状态为三个 33-bit 端点（99 bit），并复用原跨度结果；未新增
乘法器。逻辑位数不是 FPGA 实际资源数，尚未测量物理时序/资源影响。
参数为 0 时可复现原逐行检查路径，便于比较。

## 定向测试

开关两种配置都通过 215 次结果检查：含 200 次随机布局的独立全行配对
参考核对、共享 padding、重叠、取消/重启、配置快照、结果背压，以及
4-GiB 末端的重叠与恰好相邻边界。新增四种分区配置原有检查仍通过。

计时从请求接收后到 rsp_valid 首次置位，不包含响应端人为背压。
三帧整体地址范围互不相交时：

| 每帧几何 | 原逐行路径 | 快捷路径 |
| --- | ---: | ---: |
| 640×480，stride=2560 | 1494 cycles | 54 cycles |
| 4×65535，stride=16 | 196659 cycles | 54 cycles |

第一行节省 1440 cycles，约 96.39%。这仅是三帧检查器延迟，不能称为
整个 frontend 的相同比例加速，也不能外推整机 15 fps。整体范围相交时
仍保留逐行最坏开销，watchdog 必须继续覆盖它。

## 后续

本优化没有代替双槽连续成功、软件取消或预览显示集成。它减少常见独立
内存分区布局的启动开销，不改变帧缓冲所有权或显示发布语义。
