# DW 整层连续调度与逐层等待归因

日期：2026-09-12。范围：板卡无关 RTL；不替换企业外设例程，不改变算法、CPU/APB/AXI或描述符ABI。

## 1. 实际问题与优化边界

先对上轮342,287拍的64×48训练模型配置增加逐层FSM统计。每一周期分别计入engine和
adapter的一个状态，两份直方图各自必须等于同层总周期；再把逐层adapter统计与独立
累积的全任务adapter直方图核对。归属使用**adapter stage index**，包含启动/层准备，
不是MAC执行时间估算。仿真额外数组不进入生产RTL或综合。

基线`soc_layer_profile_64x48_20260912_a`完整golden通过，周期没有改变：

| 位置 | 观察结果 | 本轮处理 |
| --- | --- | --- |
| stage19：16→8 pointwise | adapter READ_RSP占27,275/42,669拍，约64% | 留待取数链路优化；不能认为增加MAC即可解决 |
| stage18：16通道DW | engine DW_START占15,165/38,800拍 | 本轮消除暖像素间重复启动/排空 |
| stage5/9/13：残差相加 | 合计44,581拍，约任务13%；主要是两路串行读和写回 | 银行别名/读写顺序需单独设计，没有放宽依赖 |
| stage20：末端3×3卷积 | 27,648实际dot输入拍，层总46,393拍 | 不在本轮改动，保留现有末端输出融合 |

现有`PIPELINE_DW_PIXELS`已允许下一像素在旧结果排空期间收集窗口，但仍给每个暖像素
发送START，最后一组给DW原语发送batch EOF。下一像素经过DW_START时要等待旧batch
输出EOF真正退休。既有DW核的`PER_BEAT_CONFIG`已能让每组窗口、权重、偏置、量化和
坐标一起经过弹性流水，因此这些像素之间没有更换整层参数所要求的排空依赖。

## 2. 生产改动

新增默认关闭`STREAM_DW_FRAME`，必须同时启用`PIPELINE_DW_PIXELS`；后者原有的
DW group streaming、缓存权重以及adapter列读/写回重叠约束不变。

参数路径为：`c1_r1_portable_soc` → `c1_r1_microstyle_system_bridge` →
`c1_r1_microstyle_cnn_top` → `c1_r1_microstyle_engine`。

只有engine改变运行逻辑，另外三个文件透传参数；没有新增SV文件、外部端口、生产
寄存器、状态、数据缓冲或MAC/RAM数组。原`c1_dwconv3x3_c8_requant_core.sv`的算术和
弹性流水不变，tensor adapter、pixel writer、DDR和控制器也不变。

处理顺序：

1. 冷的第一个像素仍逐组读权重、运算和实际排空；已有cache有效位规则不变。
2. 第二个像素在全部权重组有效后启动一次暖batch；单像素层没有这一步。
3. 后续暖像素在同一batch内运行，DW_START只准备下一组寄存器，不向忙核发出一个
   随后会被撤回的START。输入窗口缓存只有在旧像素全部组已交付乘法流水后才复用。
4. 仅“真实最后像素的最后一组”携带batch EOF。逐拍配置及坐标仍绑定实际输入握手。
5. 输出按旧的独立retire-group游标和DW核携带的x/y还原，不使用已经指向新像素的
   metadata；真正输出EOF退休后才完成本层，pixel writer仍要完成真实写退休。

取消/错误仍复用原core reset及系统AXI排空，不能为了结束连续batch丢弃总线债务。
不预提交DONE，不更改上一阶段成功排空期间的取消/错误优先级修复。

## 3. 同配置64×48结果

训练权重、彩色RGGB→ISP→CNN→DDR→显示；开启原列读/行映射复用、虚拟UPS视图、
多组dot/DW像素流水、末端输出融合等完整优化组合。真实22个逻辑层均由integer golden
计算，19个物理结果阶段仍检查全部28,608个C8输出和3,072个DDR/显示像素。

| 指标 | DW frame关闭 | 开启 |
| --- | ---: | ---: |
| 整任务周期 | 342,287 | 329,619 |
| stage15周期 | 11,501 | 10,784 |
| stage18周期 | 38,800 | 26,854 |
| stage19周期 | 42,669 | 42,669 |
| stage20周期 | 46,393 | 46,393 |

总周期减少12,668（3.701%），同频吞吐增加约3.84%；stage18周期减少约30.79%。
stage3/7/11仍分别8,372/8,374/8,373拍，表明其等待已被较长的取数过程隐藏；没有
将所有减少的START直接换算成系统周期收益。

64×48共5个DW层，第一像素的冷组START合计23。关闭时另有4,411个暖像素START；
开启时暖START只剩5次，连续准备4,406次。**直接计数**实际core输入/输出batch EOF
均28，不从总周期差倒推；MAC/读写量保持原预算。检查器核对descriptor推导的预算。

## 5. 尚未证明的事项

- 所有结果是限定BFM延迟下的功能/周期证据，不是Efinity综合、时序或板卡实测。
- 源码未新增生产寄存器/数组，不代表目标工具的LUT/FF数量必定完全相同。
- 继续保持默认关闭；目标Fmax若下降约3.70%以上，就可能抵消本轮同频收益。
- 原生640×480理想工作量下界仍8,928,000拍，未因减少启动而改变MAC工作量；
  15fps仍未证明，不能把64×48结果乘100当成原生实测。
- 后续优先检查stage19的列取数串行等待，再评估残差层的独立读和写退休调度。
  对银行别名、已呈现请求稳定性、真实BRESP/RLAST排空的要求保持不变。

本轮全部系统验证均通过既有WMI隐藏独立worker执行，不绑定Codex Windows Job，
不生成波形。六次均complete/exit0，临时项目不存在、worker已退出，保留4.820MiB文本。
最终核验见`../logs/dw_frame_closure_audit.log`；持续过程记录见`../DEVELOPMENT_LOG.md`。
