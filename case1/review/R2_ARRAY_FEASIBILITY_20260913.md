# R2-A：连续归约阵列的功能、周期和I3资源可行性

日期：2026-09-13。主线已从R1执行器的局部优化切换到R2架构可行性。
本轮完成预算模型、独立计算原型、训练数据条带验证及Ti60F225 I3核级map/PNR。
**没有替换R1整机，也没有得到新的原生640×480帧率。**

## 1. 已实现的变化

新增`rtl/r2/c1_r2_dot16_array.sv`，可选6行×16项（96乘法）或8行×16项（128乘法）。
每行拥有独立激活、权重和bias，可将行分配给不同像素/输出通道，解决旧核单一输入
广播使RGB尾层难以填满输出通道的问题。空间地址和窗口生成在阵列之外。

first携带bias，后续beat继续signed32模2^32累加，last产生该批行结果。没有独立
START事务，因此单beat与多beat归约可以相邻发射。乘积→pair→quad→oct→16项和→
累加/输出逐级寄存；输出受阻时整个算术和元数据流水冻结，输入保持ready/valid协议。
当前只能顺序完成一批行的归约，不支持交错多个未完成的累加上下文。

`c1_r2_array_host_probe.sv`用外部32-bit写接口加载全部独立激活、权重、bias，并以
行选择读回完整32-bit结果。没有用零权重/常量或仅折叠输出的激励壳代替真实可观察
计算。host壳测试逐行确认独立数据与结果访问；它仅解决资源探针端口太宽的问题，
**不是每拍可供应192/256 byte的片上存储实现**。

尚未实现：tile SRAM banking、load/compute/store调度、窗口/权重广播、DDR DMA、
量化器连接、残差数据通路、融合及任务接口。旧ISP/CPU/AXI和R1执行路径均未改动。

## 2. 重新计算的原生预算

`golden/r2_architecture_budget.py`按32×16输出tile枚举每层，不简单拿总MAC除并行数。
普通卷积归约长度为Cin×Kh×Kw，DW为Kh×Kw；每批行的归约拍数为ceil(K/16)，输出
行按像素×真实输出通道展平，tile尾单独向上取整。仍假设各层串行、操作数即时可得。
上采样view/末端identity保留已有消除方式；残差线性路径另保留172,800拍预算，
不因为计算原型没有接残差就把其工作量删掉。

| 计算阵列 | 不限速量化/不计量化排空时的下界 | 假设4路标量量化、理想重叠后的下界 |
| --- | ---: | ---: |
| 4×16，64乘法 | 8,620,800拍 | 8,620,800拍 |
| 6×16，96乘法 | 5,805,600拍 | 6,803,400拍 |
| 8×16，128乘法 | 4,396,800拍 | 5,894,400拍 |

对比R1当前映射的8,928,000拍理想下界。R2的128路并不是总MAC/128得到的
3,345,600拍：归约尾填充、DW映射、tile尾和线性路径都要付出周期。

4路量化预算使用逐层`max(array_beats, ceil(real_output_scalars/4))`，假设完善的
弹性重叠和跨向量装填，仍不是量化RTL实测。96路配4路量化即使忽略其他开销，
100 MHz下也只有约14.70 fps的上限。因此量化不能在阵列选型后才处理。

以下边界同样重要：

- 96/128路无量化限速的100 MHz上限约17.23/22.74 fps，均非实测帧率。
- 32×16方案最大单层输入乒乓有效payload为68,640 B，已计C8填充与stride/kernel
  输入范围；不含输出、部分和、参数、额外融合halo或M10K端口碎片。
- 原始宽接口每beat激活+权重分别192/256 B，即100 MHz下19.2/25.6 GB/s片上端口
  需求；这不是DDR需求。必须用广播、局部权重、banking和数据复用降低实际读口压力。

6项预算单元测试通过：原生MAC守恒、尾层重映射、tile取整、DW/view/残差、非法参数、
量化通路不能当作零开销。

## 3. 功能证据

用现有功能QAT artifact及确定性的非平凡RGB图案运行完整整数golden，取得真实
640×4条带的中间特征，而不是用任意常量填充各层。分别对stage18/19/20重新按OIHW
遍历计算signed32累加，再用独立标量量化与原完整golden的层输出逐标量核对。最终
把16项归约输入及期望累加结果送入新RTL。条带高度4，不是原生480行整帧。

每种阵列覆盖69,120个训练数据标量：40,960个DW、20,480个1×1、7,680个RGB尾卷积，
包含图像左右/上下replicate边界、RGB跨像素映射及6行配置的尾mask。

另有180个随机事务：归约长度1/9/16/17/27/48/72/108/271，带signed8极值、signed32
bias边界、模2^32溢出、零/部分/全行mask。局部未完成归约复位后，完整向量流重新
执行；这不是整机AXI中止恢复测试。

| 配置 | 输入beat | 输出向量 | 测试总拍 | 输出阻塞拍 |
| --- | ---: | ---: | ---: | ---: |
| 96路，无背压 | 17,421 | 11,701 | 17,429 | 0 |
| 96路，随机背压/输入间隙 | 17,421 | 11,701 | 26,840 | 7,321 |
| 128路，无背压 | 13,260 | 8,820 | 13,268 | 0 |
| 128路，随机背压/输入间隙 | 13,260 | 8,820 | 20,473 | 5,551 |

无背压均核对末次接收拍−首次接收拍＋1等于输入beat数，证明输入连续无START空拍，
不只是通过平均周期估计。两种host壳配置额外完成24/32次逐行读取检查，并验证
单beat、多beat及保持结果。总计4种阵列配置＋2种host配置通过。

这些测试由Icarus执行；本轮没有调用Vivado或xsim。旧22层SoC没有重跑，因为未修改
其生产路径，不能把本轮算术条带测试称为新SoC整网golden通过。

## 4. Efinity实际资源：未自动获得双INT8打包

工程明确使用Ti60F225 **I3**，与企业板卡例程的timing model一致；100 MHz约束。
通过既有WMI外层在脱离当前Windows Job的worker中执行map+PNR，无板级PLL/pin/IP。
每种阵列先运行a，再以相同源码运行b补齐资源摘要，结果一致。

| 含host壳的原型 | 96路 | 128路 |
| --- | ---: | ---: |
| 物理DSP | 96/160（60%） | 128/160（80%） |
| 物理XLR | 5,168/60,800 | 6,853/60,800 |
| map FF（含加载寄存器） | 4,765 | 6,333 |
| Memory blocks | 0 | 0 |
| 核内最终最大周期 | 4.271 ns | 4.359 ns |
| 核内路径估计Fmax | 234.137 MHz | 229.410 MHz |
| 100 MHz setup slack | +5.729 ns | +5.641 ns |
| hold slack | +0.090 ns | +0.090 ns |

map分别保留96/128个EFX_DSP24，PNR物理DSP也分别96/128。**当前推断写法没有自动
把两条INT8乘法打包到一个物理DSP**。不能把厂商支持Dual模式等同于本设计已实现
48/64 DSP，更不能只按乘法数的一半做整机预算。

上述Fmax只属于该独立加载/观察壳内路径，不是完整CNN、DDR或整板可运行频率。
量化器和tile SRAM均不在资源内；Memory=0意味着这个原型尚未实现片上供数存储，
不是整个新架构不需要RAM。host参数tag宽8，直接MAC功能测试宽16。

资源提取脚本原本遗漏不含关键词的层级表行和XLR计数，本轮补充保留规则。b运行
实际文本写的是`XLRs:`，新自动字段初版只匹配`XLR Cells:`，因此b的历史summary中
该字段为null；随后修正未来运行的规则，并由独立检查器直接核对已保留的原始
`XLRs:`行，没有手工改写旧summary或再运行第三轮PNR。2项正向/3项负向解析检查通过。

独立检查器另核验状态、真实I3运行命令、DSP原语/物理总数、XLR总数和比例、setup/
hold均非负。证据见`logs/r2_resource_gate_20260913.log`。

## 5. 下一道门槛与当前选择

本轮不锁定终版阵列规模。**优先进入96路候选的量化＋真实SRAM供数原型，128路保留
作对照**，原因是96路还剩64个DSP，而128路在未接量化/ISP/CPU前仅剩32个。

- 先评估6路量化配96路阵列；4路量化已经在100 MHz预算中否决该组合，不能继续
  假定减少量化DSP不影响速度。
- 将150 MHz作为待验证的完整计算/存储子系统目标，同时保留100 MHz对照。裸核
  约230 MHz不代表带bank地址/选择器、量化及结果写入后仍能达到150 MHz。
- 实现真实同步RAM bank、权重/激活广播和有界乒乓缓冲，用原生宽度DW/PW/尾卷积
  条带证明读取端口可以持续供数；根据实际tile交接/量化阻塞重新计算整网周期。
- 加上CPU/视频固定资源预留后再决定阵列、tile和融合粒度；若需显式Dual DSP，必须
  单独做算术与物理打包证明，不能用不等价的窄累加替换现有signed32规则。

当前全系统最快已验证执行仍是R1的64×48、299,189拍。R2-A证明新的计算组织能够
连续发射并在I3上实现，尚未证明片上供数、DDR竞争、整帧吞吐或比赛画质。
