# 写区域与多个读区域的配对检查

日期：2026-09-11。

## 实现与用途

`c1_frame_triple_layout_check.sv` 增加静态参数 `CHECK_PAIR_MASK[2:0]`，默认 `3'b111`，保持现有输入/处理/预览三帧互斥检查不变。bit 0、1、2 分别控制 (0,1)、(0,2)、(1,2) 的重叠检查。

未来捕获写入保护可将 frame 0 作为候选写区域、frame 1/2 作为显示读区域，使用 `3'b011`：禁止两组写读重叠，但不因读读别名而误报。所有区域的尺寸、对齐、末端和 arena 合法性仍然检查；掩码不能绕过这些检查。

复用已有顺序末端计算、33 位半开地址范围和精确行区间比较。没有引入多组组合乘法器，也没有把比较退化为基址相等或整个 stride envelope 重叠判断。行间 padding 可共享的语义保持不变。

## 已完成验证

`tb_c1_frame_triple_layout_check.sv` 新增 `WRITE_VS_READERS` 模式，独立逐行 oracle 相应只检查写读配对。FAST_ENVELOPE 开/关各运行 215 项检查，其中各 200 个随机布局；每组随机布局分别得到 58 个合法、142 个重叠。定向用例覆盖读读别名、写读别名、4 GiB 末端、相邻范围、非法几何、输入快照、响应背压与取消后重启。

通过标记为 `C1_FRAME_WRITE_READERS_PASS`，不冒用“三对互斥通过”标记。默认模式、性能模式、arena 模式和新增模式共 10 个定向配置通过。原性能测试仍为不相交 envelope 54 周期；此数字不代表未来系统级多个活动区域检查的总耗时。

## 接入边界——尚未修复覆盖缺陷

本轮为活动显示区域保护完善已有检查器，**尚未将新模式接入捕获 writer 启动路径**。现有 frontend 实例仍使用默认三对检查。`RTL_CAPTURE_DISPLAY_ALIAS_20260911.md` 中六个捕获覆盖显示的失败用例仍是待修复的验收项，不能因比较模块通过而宣称系统已具备保护。

接入必须一并解决生命周期：

- 捕获表项与保护区域应在请求边界快照，检查期间的 live CSR 或显示元数据不能改变比较对象。
- 当前显示、已发布待显示及尚有读事务未退休的旧显示区域，不能因槽号换帧就提前释放物理保护。
- 如果检查过程中产生新的保护区域，应由统一分配顺序保证无冲突，或在启动之前重新验证版本；只冻结比较输入并不足够。
- cancel 只能丢弃未启动检查；已经启动的 writer 必须保持区域占用直到其外部响应退休。
- capture、processed、preview、tensor 的真实写入口需要一致的规则，不能仅在孤立模块内证明数值比较正确。

这属于原地址隔离修复的中间步骤，不是替代完整修复的新目标。本轮未启动 Vivado，也未生成波形。
