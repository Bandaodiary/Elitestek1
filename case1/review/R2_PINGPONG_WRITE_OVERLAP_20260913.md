# R2-C8：双缓冲写回与计算重叠

日期：2026-09-13。R1、C5、C6、C7 RTL入口均保留；C8未替换默认portable SoC。

## 1. 结论与边界

完整640×480、22节点图在xsim逐项通过golden：**9,289,054拍，按150MHz折算16.15fps**。
这是与C7相同的共享读写1.2GB/s、逻辑命令额外延迟20拍模型；没有改变模型权重、量化、
分辨率、外部布局或黄金算法。C7对应12,086,084拍/12.41fps，本阶段减少2,797,030拍，约23.1%。

首次跨过这一核级模型的15fps门限，不等于实际AXI/DDR/CPU/视频整机或板测完成。
150MHz下每帧预算10,000,000拍，剩余710,946拍（约4.740ms、预算的7.1%）。
真实burst切分、DDR刷新/仲裁、视频竞争和CPU操作可能消耗这部分余量，不能省略下一阶段。

最终Efinity Ti60F225/I3核级map＋PNR通过150MHz：38,819XLR、160RAM、112DSP，
setup/hold余量+0.540/+0.031ns。相比C7多16RAM、DSP不增；较小的hold余量和整机
集成后可能变化的时序必须继续检查。

## 2. 为什么双缓冲还需要调度优先级

C7已经能在旧行写回时预取下一行，但计算必须等旧写回结束。共享存储总线下，读与写
彼此重叠不能消除总服务时间，原生周期接近“6.116M计算拍＋5.899M总线服务拍”的串行和。
继续微调几拍状态机或单纯增加outstanding，无法追回需要的约2.086M拍。

C8先解开writer收集/发送互斥，又加入实际RTL预取优先控制：

1. 计算新行期间，writer发送旧行。
2. 计算结束后，特征池空闲，优先预取下一行，writer暂缓获取新发送字。
3. 预取完成且有空writer页后立即计算，不再要求全部旧写响应已经返回。
4. 若writer页已满，则等待期间继续发送；层末及错误排空时也必须继续发送，避免自锁。

这不是修改内存模型使其“偏爱”C8。相同memory model仍按原规则提供共享读写服务；
是RTL本身减少预取阶段的写请求，把可延后的写回放到计算阶段。

### 3.1 两页所有权

writer保持16个字节bank，每bank深度从1024增至2048；最高地址位选择两个独立页。
一套重排逻辑向collect页写入，另一读端从send页输出，不复制MAC或重排逻辑。
逻辑结果存储从16KiB增至32KiB，Efinity实际从16个Memory Block增至32个。

页在行start握手时保留，在该行写响应握手后才释放。每页分别保存地址、宽度、通道数、
group数和输出字数；collect侧mode/RGB配置独立锁存，send侧再锁存该页自己的元数据。
这样新行的配置或地址不会覆盖仍在发送的旧行。发送顺序与分配顺序一致。

`write_count`计入收集中、已收齐待发以及发送/待响应的页，最大为2；不是AXI outstanding数。
当前发送器仍一次只处理一个外部行写命令并等待其响应，行接口仍不是物理AXI。
testbench逐拍核对graph计数与writer allocated页数及延迟done脉冲之间的守恒关系。

### 3.2 安全暂停发送

`stream_enable`只限制获取新的RAM读字，以及从空闲态开始新的发送命令。
若数据已经在`valid=1,ready=0`保持，切换到预取优先时不会撤回valid或改变data/last。
该字可以继续完成握手，后续新字才暂停。命令一旦发出，同样保持到握手。

预取阶段包括cache查找、地址流水、行请求/接收；ISSUE等待空页、计算、层末等待及
ERROR_DRAIN均允许writer推进。因此不会因“页满需要写回，但又一直禁止写回”自锁。

### 3.3 错误与提交

写响应错误可能发生于下一行仍在计算时。C8不立即丢弃该计算的结果，而是继续接收
已发起的算子任务，让已保留页全部发送/响应完成，同时排空已接受的读请求；禁止
发起新的算子任务，最终报告整帧失败。层末必须等待全部页响应后才提交或切换参数。

错误后无复位重新启动帧时会清空行缓存标签、重新装载参数和输入，不能读取失败帧遗留值。
新增系统复位测试同时复位graph和memory endpoint；不将该证据声称为局部reset下AXI
事务排空，也没有实现CPU cancel协议。

## 4. 功能与定向验证

最终数据通路RTL矩阵：4×4、12×12、32×32、640×12，各连续/随机背压两种配置，
共18正常帧、24故障帧；2,448,464个有效标量对应167,060个128位正常写回字逐项一致。
只初始化输入RGB和真实训练参数；每个后层读值来自此前RTL写回，并逐字检查生产者。

额外验证：

- 共享1.2GB/s、20拍延迟的小帧连续/随机背压：6正常帧、24故障。
- 每128拍仅开放最后32拍写服务的定向压力：3正常帧、12故障，7,364拍暂停优先级下
  已保持写数据稳定，出现63,601拍双页占满；正常压力帧未放宽写端限制。
- 六种在途系统复位：收集、数据背压、两页收集、写响应等待、计算/写同时在途、
  双页占用且预取在途；每次之后均完整重启并通过golden，共6正常重启帧。
- 两次真实层间RAM数据/生产者破坏，均在stage1检出。
- 10项日志证据破坏测试被审计脚本拒绝，包括错误提交、页数和虚假计算/写回重叠。
- 最新测试台xsim小帧为17,232拍、读3,143字/写756字，与Icarus连续共享模型相同。

12种故障保留C7的参数/数据错误、early/late last、非法命令、普通/最后写错误等，
新增第11种“旧写错误时新计算与两页在途”、第12种“两页占用时预取读错”。
故障10/11为了确保目标并发窗口，定向提早完成旧行写数据；仍遵守共享服务速率，
只是这两种故障不叠加随机/长写端节流。性能数据全部来自无故障正常帧，不受该安排影响。

严重节流下，最初两个故障测试可能等到计算/读窗口消失后还要求在该窗口返回错误，
形成测试台等待自锁。这两个旧运行已针对其准确vvp子进程停止，保留失败记录；

## 5. 消融与原生性能

32×32消融全部采用同一共享1.2GB/s/20拍模型，RAM容量均为两页：

| 计算/写重叠 | RTL预取优先 | 实测图周期 | 计算期间实际发送字/帧 |
|---|---|---:|---:|
| 关闭 | 关闭 | 56,848 | 0 |
| 开启 | 关闭 | 52,900 | 851 |
| 开启 | 开启 | 50,562 | 4,420 |

每帧读/写均为7,389/4,768个128位字。不是通过改变图内容、访问次数或内存模型实现的消融收益。
无带宽限制的640×12连续周期为206,079，对比C7的217,312仅小幅下降；这一短帧指标
不能取代共享总线完整原生帧，更不能由此否定/宣称15fps。

原生运行`c8_xsim_native_20260913_a`：

|---|---:|---:|
| 分辨率 / 提交节点 | 640×480 / 22 | 640×480 / 22 |
| 实测图周期 | 12,086,084 | 9,289,054 |
| 150MHz折算帧率 | 12.41fps | 16.15fps |
| 特征读128位字 | 1,516,800 | 1,516,800 |

C8有1,423,440个写字在算子busy期间实际握手，占写字数约99.5%。
原生测试的外部读/写同时在途计数为0，是预取优先调度的预期结果；核心改进是
“计算与写”重叠，不应为了保留C7的“读与写”重叠计数而拒绝这个调度。
逐项检查19实际写回节点的21,043,200个有效标量对应结果，包含最终RGB写回。
输入仍是确定性测试图案，参数来自真实训练artifact；未进行新的风格主观质量或摄像头测试。

存储模型是每两核心拍合计服务一个128位读生产或写接收，具有一格弹性读响应；
额外20拍延迟按逻辑行命令计，不按切分后的物理burst计。测试台时钟为10ns，报告
150MHz帧率使用拍数换算；150MHz可达性由独立Efinity核级时序提供。

## 7. 下一阶段与复现

下一阶段为真实128位AXI行DMA，不再增加MAC或继续围绕单页writer微调：

1. 读写行描述符按最大burst长度和4KiB边界切分，按行重建last及错误汇总。
2. 有界多outstanding隐藏每个burst的命令延迟；保持读返回顺序及全部B响应的行完成屏障。
3. 尊重C8写端合法暂停，避免DMA/DDR调度因AW已经进入队列而阻塞必要预取；这需要
   实际桥接协议和服务模型联合验证，不能只看核级ready/valid。
4. 完整原生帧再次逐项比较golden，加入随机AXI延迟/错误/边界以及共享带宽服务，
   检查710,946拍剩余预算是否够用，再引入CPU/视频竞争和实际Efinity DDR平台。
5. 对接CPU寄存器/中断、参数上传、缓存一致性、输入/输出格式及帧所有权；完整SoC
   重新综合、PNR和板测后，才讨论比赛整机15fps。
