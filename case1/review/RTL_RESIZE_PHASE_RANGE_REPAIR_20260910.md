# Resize 相位累加范围修复

## 问题与边界

`r1_resize_request_q16.sv` 的配置接口允许 signed32 Q16.16 初相位/步长与 16-bit 输出宽高，但内部相位同样使用 signed32。多次累加会产生模 2^32 回绕，后续边界夹取面对的是错误坐标。

原 `c1_r1_resize_pipeline.sv` 文档要求调用方保证相位演进不溢出，但硬件没有检查这一额外前提。本次修复消除这项调用方负担，而不是改变原先不溢出配置的插值算法。完整流式 pipeline 仍要求 y_step 非负：两个行缓存不支持倒序访问已经丢弃的旧行。坐标原语本身仍可生成负 y_step 请求。

修复前，新测试在第二个请求复现：初相位与步长均为 `0x7fffffff`，正确相位为 4294967294，8 像素宽图的 x0/x1 应为 7/7；旧累加器回绕到 −2，实际输出 0/0。失败信息是 `resize phase mismatch n=1`，不是超时。

## 修改

- 内部 x/y 相位从 signed32 扩为 signed48；floor 与夹取比较输入同步扩为 48 位。
- 初相位和步长配置接口仍为 signed32，输出坐标仍为 16 位，Q0.12 权重、舍入、边界夹取、ready/valid 和完成时序不变。
- 最长轴 65535 最多累加 65534 次。`phase0 + index*step` 的最小值不小于 `−65535*2^31`，最大值不大于 `65535*(2^31−1)`，均在 signed48 范围内，因此不依赖软件预先计算溢出界限。
- 不用乘法器计算硬件坐标；RTL 仍按握手逐次相加。修改增加 32 个相位寄存器位，并扩大相应加法/比较逻辑。实际映射、面积与时序需要另做综合，不能由本次功能测试推断。

涉及生产文件：`rtl/video/r1_resize_request_q16.sv`、`rtl/video/c1_r1_resize_pipeline.sv`（后者仅更新接口约定注释）。

## 定向验证

新增 `sim/tb_c1_resize_phase_range.sv`，用独立 signed64 乘加计算每一输出坐标的参考相位，不使用 DUT 内部累加器。覆盖：

1. 双轴初相位与步长均为 signed32 正极值。
2. 双轴初相位与步长均为 signed32 负极值。
3. x 输出轴 65535，正极值累加。
4. x 输出轴 65535，负极值累加。
5. y 输出轴 65535，正极值累加。
6. y 输出轴 65535，负极值累加（坐标原语级，不表示流式行缓存支持负 y_step）。
7. 13×9 输出，不同横纵正小数步长、负初相位。
8. 13×9 输出，横向负小数步长、纵向正小数步长。

所有用例核对输出坐标、四个采样坐标、四个权重、最后一个请求及 done；请求插入固定周期背压，比较完整 149-bit 请求载荷在停顿期间不变。修复后 8 项全部通过，最大轴长 65535。

原有 `generate_r1_resize_primitive_vectors.py` + `tb_c1_r1_resize_primitives.sv` 也通过：50 配置、3211 个坐标请求、10726 个插值向量。临时向量和编译镜像使用独立临时目录，测试后逐文件清理。

重现定向范围测试：

```powershell
& case1/scripts/run_iverilog_review_fixes.ps1 -TestTop tb_c1_resize_phase_range -Python <已有Python解释器>
```

## 尚未由本修复证明的内容

极值范围测试是坐标原语级；不等价于极大尺寸的完整行缓存/DDR 图像验证。13×9 两组用于核对坐标与权重，不替代完整 SoC 非等比例缩放后的逐像素比较。原生帧率、Efinity 映射和板上性能均不是本次结论。
