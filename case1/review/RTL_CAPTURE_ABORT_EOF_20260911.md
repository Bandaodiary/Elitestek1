# 捕获活动期取消与 RAW EOF 同拍修复

日期：2026-09-11。

## 新覆盖

扩展可暂停相机测试，先发送一帧，启动实际 ISP，并阻塞 RGB 消费端。观察到首个 `m_valid` 时，明确要求捕获状态仍为 `ST_STREAM`，证明 RAW 输入和 RGB 输出在流水线内同时存在，再将 abort 保持 12 个核心周期。

FIFO 16/32 项 × 相机半周期 3/7 ns 四组均通过：42 个 RAW token 排空，abort 只报告一次，未消费的 RGB 被丢弃；无复位启动后续两帧渐变图像，40 个 RGB 像素及帧标志符合解析期望。该测试的 RGB sink 在取消前已经阻塞，因此“无输出泄漏”不代表撤回此前已经被下游接受的数据。

## 发现并修复的 EOF 竞争

增加独立边界用例，在 `raw_fire && fifo_eof` 的接受沿同时置 abort。旧 RTL 超时：`ST_STREAM` 的 abort 分支无条件转入 `ST_DRAIN_RAW`，但 RAW FIFO 在该沿仍正常消费 EOF；清理状态随后等待一个已经消费掉的 EOF。

`rtl/top/c1_r1_capture_frontend.sv` 现在在活动帧进入错误清理时检查该沿是否已消费 EOF：

- 已消费：直接转 `ST_RECOVER`，等待 ISP 自身流水线退休。
- 尚未消费：保留原 `ST_DRAIN_RAW` 路径，继续向 ISP 送完本帧 RAW/EOF，同时禁止新的 RGB 入输出队列。

abort 和输出 FIFO 溢出入口具有同一种转移错误，两处均采用该判断；abort 计数与输出 FIFO 清空机制不变。本轮直接注入并验证的是 abort/EOF 同拍，尚未单独注入“输出 FIFO 溢出与 EOF 同拍”的组合。

EOF/abort 定向用例先在旧代码超时，再在修复后通过，并完成后续两帧无复位恢复。没有强制修改内部状态、伪造 EOF 或通过复位绕过清理。

## 结果与边界

捕获定向 **24 配置通过**，含上述 4 个活动期场景与 1 个 EOF 同拍场景，既有未知值负测试也继续执行。最终全量 Icarus **458 配置通过**，进程退出码 0。旧 compute-ingress 偶发失败未重现，仍未认定根因。

这仍是捕获前端到 RGB 流边界的验证，不包含已被 DDR writer 接受的写事务；DDR 写响应排空沿用已有系统级责任。缺失 EOF 时的有限恢复政策、活动期源协议违例的完整 SoC 自动处理及原生分辨率性能尚未由本次测试证明。

本轮不运行 xsim、综合或板测，不生成波形，临时编译文件与向量由回归脚本清理。
