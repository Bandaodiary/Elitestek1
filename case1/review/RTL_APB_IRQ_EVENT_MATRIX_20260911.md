# APB 中断事件与软件清除矩阵

本轮检查 CPU 可见的中断/诊断路径，生产 RTL 未改。
`c1_apb_csr.sv` 已对五个 IRQ 位分别使用“清除位有效且本周期无新事件”
条件，因此新事件应优先于 W1C。新增独立测试将这项契约变为可复现证据。

## 测试

`tb_c1_apb_irq_events.sv` 穷举 32 种 W1C 掩码 × 32 种同步事件组合，共
1024 组合。每组先设置五个 pending 位，随后真实 APB ACCESS 与事件在
同一采样沿发生，检查结果为 `(old & ~clear) | events`，以及 IRQ 输出
正确受 enable 掩码控制。测试未 force 内部状态。

附加检查：低字节 strobe 关闭时不得清 IRQ；W1C 清 IRQ 不擦除错误码/
地址；reset 清 pending；统计清零与 done 同周期时统计计数按现有契约
归零，但 done IRQ 仍保留，不能把统计清零等同于清通知。

定向 Icarus **1 配置通过，退出码 0**，PASS 标记注明 1024 组合和上述
附加检查。已加入统一 runner 的必需标记列表；无波形，临时编译与向量
由脚本清理。全量列表增加一项，但本轮未重跑全量，最近完整结果仍为
597 配置，不能写成本次 598 配置已全部通过。

## 软件约束与范围

IRQ_STATUS 是 sticky 位，不是事件队列：同类事件连续发生而软件尚未清除
时会合并；不能仅数中断边沿来计帧。ERROR_CODE/ADDRESS 是最新故障记录，
不是多条故障 FIFO。软件应先读取需要的状态/诊断，再写相应 IRQ W1C。
该测试证明 CSR 同步域行为，不证明 CPU 中断入口、外部 CDC 或操作系统
中断驱动；本轮没有新增相应平台假设。
