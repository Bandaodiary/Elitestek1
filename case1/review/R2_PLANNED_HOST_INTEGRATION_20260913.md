# R2-C18：生成式执行计划接入完整主机与视频系统

日期：2026-09-13。本阶段保留 R1、C8～C17 和 C15 默认候选入口，新增独立 C18 系统；不替换比赛模型。

后续C19在不修改C18生产RTL的条件下完成系统SLVERR/多B债务排空/失败输出隔离/无复位恢复，见[C19记录](R2_HOST_ERROR_RECOVERY_20260913.md)。共享检查器按真实DONE修正绝对完成时刻+1（完成间隔和FPS不变），C18局部复核为`logs/r2_c18_gate_20260913_c.log`。**18:33 C18自身原生六帧已验收通过，最坏15.3145fps@150MHz，见下方补充与`logs/r2_c18_native_gate_20260913_a.log`。**

## 1. 本轮实际改动

C16/C17 已证明同一行执行器能够运行生成的计划和配套参数，但此前证据主要位于 CNN 行接口。C18 将原 22 项模型的配套包接入真实 RGBX 行 DMA、四主机 AXI、帧所有权、采集、双图显示和 CPU/APB3/IRQ 封装。

```text
c1_r2_planned_host_system                 新独立顶层
├─ c1_r2_cpu_axi_adapter                  保留 C13 普通 DDR/ID/窄访存适配
├─ c1_r2_host_control_bridge              保留 C15 APB3、诊断页与 IRQ
└─ c1_r2_video_planned_system             保留 C14 帧调度和视频数据通路
   ├─ capture / scanout / fresh_leases / CSR / AXI fabric
   └─ c1_r2_planned_rgbx_axi_graph
      ├─ RGBX/P2C8 行转换与 AXI DMA       保留 C12
      └─ c1_r2_planned_pingpong_graph     保留 C16 执行器
         ├─ c1_r2_microstyle_plan         C17 包内生成的 execution_plan.sv
         └─ 加载、96 MAC、量化、双页写回 保留原计算阵列
```

新增三个 wrapper 和一个资源探针，与对应旧文件去掉注释/空白后直接比较：除模块名称和被替换的子模块类型外，代码一致。没有修改旧生产 RTL，也没有为另一个图手工修改执行器层号。

RGBX 转换由每次任务锁存的输入/输出地址槽选择，不由固定 stage 0/20 选择。对外仍为 RGBX32，每个 128-bit beat 四像素；中间张量仍为 P2C8。单次任务地址快照、真实 B 响应退休、DMA 债务排空以及协议故障需协调复位的合同不变。

仿真源闭包直接取自新 XML，共 32 个生产源文件（不含探针）；必须且只能含一份 `c1_r2_microstyle_plan`。原模型使用 `model/r2_microstyle24_bound_plan/`，结构变更试验使用 `model/r2_drop_res1_bound_plan/`。不得同时加入 C16 独立静态表和包内表。

硬件计划是编译期生成表，不是软件任意微码。拓扑变化仍需重新生成并综合；权重、bias 和量化命令来自与计划匹配的参数镜像。当前不具备 FPGA 运行期自动识别错配包的机制，软件/构建必须遵守配套合同。

18 项删块图仅验证外围没有隐藏的 22 层依赖；未重训或证明风格质量，不作为原比赛模型的加速成绩。算子、通道、尺度、三工作区生存期和融合限制见 [C17 报告](R2_BOUND_PLAN_PACKAGE_20260913.md)，不宣称任意 CNN 兼容。

测试中的 CNN 输入只来自实际采集写入的共享 RAM，每笔中间读取核验 DAG 生产者和帧标签，写结果逐项对照独立 Python golden。显示检查实际写入的结果，而不是将 golden 直接注入内存。计划有效信号在实际 stage commit 时检查；TB 的生产者映射改为读取由逻辑 DAG 独立生成的表。
