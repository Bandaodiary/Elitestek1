# 可选 APB 捕获恢复入口

## 硬件与软件契约

`c1_apb_csr` 新增默认关闭的 `ENABLE_CAPTURE_RECOVERY`；portable SoC 随
`ENABLE_EXPLICIT_CAPTURE_RECOVERY` 启用，复用已经验证的全局取消和双域
FIFO 恢复路径。硬件外部请求优先，软件不可写入源停止确认。

| 地址 | 含义 |
| --- | --- |
| 0x008 bit16 | CAPABILITY：存在恢复寄存器 |
| 0x130 | 命令：写 1 请求恢复；写 2 清完成状态；读回 0 |
| 0x134 | 只读状态：bit0 enabled，bit1 ready，bit2 busy，bit3 sticky done，bit4 source quiescent |

禁用时 0x130/0x134 仍是非法地址，访问返回 PSLVERR。应先读能力寄存器，
不要通过制造总线错误探测功能。状态写入、同时请求并清除（3）、有效字节中
任一保留位为 1，以及 not-ready 时请求恢复都返回 PSLVERR 且无命令副作用。
未使能字节不参与命令解码；全零有效写入为无操作。

恢复请求在 APB 完成的同一上升沿接纳，不产生延迟一拍的待执行命令。
因此不能在总线传输结束后才改变目标就绪条件。外部硬件 request 为高时
软件 ready 为低，软件请求返回错误。APB BFM 已改为在上升沿采样 PSLVERR，
不是在后续下降沿读取已被该命令改变的组合状态。

sticky done 在软件新请求接纳或写 2 时清除，完成事件置位。新请求与旧完成
同周期时新请求清除优先，避免旧事件被当成新请求完成；写 2 与完成同周期
时完成优先。该状态表示观察到的完成，外部硬件请求不会自动清除
之前的完成记录。软件请求会先清除旧 done，不应在未发起新请求的情况下
把历史 done 当成当前操作完成。没有新增完成 IRQ。

## 软件使用顺序

1. 查询 CAPABILITY bit16，保存现有错误码、地址和必要诊断。
2. 请求摄像头/输入源停止，通过实际板级控制路径提供同步后的停止确认。
   可先发恢复命令再等待确认，但必须保证恢复完成前源不恢复数据输出。
3. 软件读取 ready，写命令 1；若请求竞争导致总线返回错误，不能认为已接纳。
4. 轮询 done；同时需要用 BUSY 判断系统整体是否允许新任务。等待超时不能
   伪造源确认、总线排空或 FIFO 复位完成；两个时钟必须运行。
5. 完成后恢复源，使用原 START 流程发起新任务。配置写入与恢复串行化。

当前仅提供头文件地址/位定义，未提供板级停止源驱动或 C 层轮询封装。

## 验证结果与剩余项

SoC smoke **19 配置通过，退出码 0**，其中 4 个启用恢复的配置覆盖排队/
直连写 fabric 与寄存/直连 fatal ticket。新增软件恢复、读状态、清完成、
忙时拒绝 START/重复恢复、非法命令、只读写保护、字节掩码、功能禁用地址
报错及能力发现检查。APB mux 定向 **1 配置通过**：113 次传输，包含等待、
随机访问及错误传播。
