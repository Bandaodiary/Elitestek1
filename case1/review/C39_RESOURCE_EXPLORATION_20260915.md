## 2. 第一优先级：裁剪官方CPU平台，不动96路计算并行度

### 2.1 当前是Standard，Lite值得独立A/B

实际官方[settings.json](D:/contest/Ti60F225_DemoBoard_v4/08_ti60f225_soc_demo/09_Ti60F225_co_debug_demo/par/ddr_demo_ti60/ip/soc/settings.json)为`SOC_MODE=0`，即Standard；I/D cache各4KiB、单路，FPU关闭，额外AXI-A和外部DDR入口开启。

官方支持Lite及统一系统时钟选项：Lite以CPU性能和部分高级功能换面积；统一时钟可避免CPU内部DDR跨域逻辑，但受最慢时钟域限制。[官方配置指南](https://www.efinixinc.com/docs-html/rv32-sapphire-ug/topics/riscv-customize-sapphire.html)。这不等于降低CNN的MAC数量：当前CNN有独立总线主机，CPU原则上负责控制，但实际BSP访存、初始化和中断响应仍须验证。

本地工具的[生成器](D:/ELS/Efinity/2026.1/ipm/ip/efx_soc/efx_soc/generator/soc_gen.py)632行附近明确：只有`SOC_MODE==1 && DDRCLK_DOMAIN==1`才生成`--noDdrAClock`。因此原settings虽写`DDRCLK_DOMAIN=1`，**在Standard模式并没有启用这一Lite功能**。不能仅把外部两个时钟接同一根线就假定内部CDC已消失。

实际MAP层次中，CPU DDR的`BmbCcFifo`占17 RAM，外部DDR入口的`Axi4CC`占5 RAM；这是可审计的22块RAM归属，**不是已经证明可净省22块**。重新生成Lite/裁剪接口后结构、深度和映射可能变化。CPU缓存各占6 RAM，因此不能把CPU全部48 RAM归咎于cache，也不宜先关掉指令缓存。

建议四个独立配置逐个比较，不能一次混改：

1. **S0：原Standard**，保留C38来源作为对照。
2. **S1：Standard只裁掉确定不用的两个AXI接口**，保留CPU DDR-A、APB、UART、I2C、必要GPIO及调试。
3. **S2：Lite、统一100MHz、保留缓存/整数乘除及调试**，先保持CPU DDR带宽取向；实际可用参数以新生成IP为准。
4. **S3：在S2基础上单独比较AXI面积取向或较小D-cache**；不是默认关闭全部cache/调试。

必须保留数据宽128位与当前ID/地址接口合同，或明确修改适配器并重新测试；Lite生成的新顶层、BSP、ISA/ABI、内存图与中断设置都不能沿用旧文件而不核对。C38生成器当前绑定原端口，需给新CPU另建来源合同。只在独立目录用官方IP生成器生成，不改受保护RTL或厂商安装目录。

## 3. 第二优先级：量化舍入的等价窄化

实际源：[c1_requant_bank8_compact.sv](../rtl/cnn/c1_requant_bank8_compact.sv)。六个有效通道的路径是32×18乘法→符号/幅值→52位加舍入偏置→右移→INT8饱和。C29已经缩小了移位后的记录，本次不能把那部分重复算成新优化。

对非负幅值m、合法移位s=0..47：

```
s = 0:  round(m, s) = m
s > 0:  floor((m + 2^(s-1)) / 2^s)
      = (m >> s) + bit(m, s-1)
```

因此可保持五级弹性流水及II=1，改成：

```
乘法 → 幅值 → {商低8位, 商高位非零, 舍入位, 符号}
     → 9位加法并合并溢出 → 原饱和/激活
```

第三阶段的数值/控制存储由每通道`52+1+6=59`位变为`8+1+1+1=11`位，**源级候选净少48×6=288位寄存器**，同时消除该路径的52位舍入加法和动态宽偏置生成。不是288 XLR的实测保证；右移、溢出检测与布线仍可能占逻辑，需要综合确认。32位累加、18位乘数、全48种移位及INT8规则不变，DSP节省尚无依据。

已经执行[算术探针](../golden/c39_requant_identity_probe.py)：106,812次中间记录比较、213,624次输出比较；全部48种移位、signed32/signed18输入极值、舍入中点、±127/128饱和和255→256进位边界均覆盖。去掉舍入位、去掉进位溢出两类错误分别造成9,854和256次输出差异，均被检出。[实际日志](../logs/r2_c39_requant_identity_20260915a.log)。

符号乘积最大幅值为2^48，合法偏置不会导致原52位加法回绕；上述恒等式适用于该实际输入域。**这只是算术验证，不是RTL握手/复位/回压/时序证明。** 下一步应独立实现候选，用原五级模块逐拍对照，加入中途复位及每级停顿，然后做同约束叶级、C37整机和C38联合资源A/B。

## 4. 第三优先级：操作数搬运和窗口缓存重构

可明确定位的宽数据结构：

- [C37窗口存储](../rtl/c37/c1_r2_partitioned_window_store.sv)：两槽×768位，输出768位二选一，动态行/奇偶银行映射。
- [encoder feeder](../rtl/r2/c1_r2_encoder_lane_feeder.sv)：两槽×896位声明、128位动态分块选择；尾部常零位会被综合消去，不能把全部声明位当作FF实占。
- [row engine](../rtl/c37/c1_r2_cnn_row_shadow_engine.sv)：1597位弹性请求，其中两组操作数各768位。
- [空间feeder](../rtl/c37/c1_r2_spatial_partitioned_feeder.sv)：不同算子选择及768位操作数暂存。PW/encoder存在多lane共享输入向量，而DW/RGB有不同复用模式。

中等风险方案是**模式化操作数打包**：在请求寄存器中保存共享输入向量及少量选择信息，到MAC入口再静态展开；所有模式仍要有足够容量，不能拿PW单模式的128位代替通用768位。另一候选是将encoder两槽重排为按K16分块的银行存储，降低大范围动态选择；并研究用BRAM交换部分FF，但宽写入和两个C8分组组装的端口需求不能忽略。

不推荐直接删除第二个槽或绕过弹性请求级：二者分别用于预取重叠和时序切分，可能把省资源变成供数气泡或更长组合路径。简单把重复mux写成共享wire也不保证有收益，工具可能早已做公共表达式合并。必须看实际同模型映射，而不是只比较SV行数。

## 5. 有潜力但不应第一步做的方案

| 方案 | 潜力与当前限制 |
| --- | --- |
| 24位累加/更窄量化乘法 | 必须证明每层bias和所有归约前缀的最坏界；当前接口允许完整32位bias和模2^32累加，直接截位会改变合同。应保留通用宽路径或做受限配置准入，不只凭几张图未溢出 |
| bias沿加法树单支提前注入 | 可减少五级192位bias搬运，但会加宽树的一条分支；不能把960位bias声明全部计作净收益。需要独立时序/位精确A/B |
| 双读端口共享权重副本 | 当前42 RAM是六份七块打包权重；数学上可研究三份双读，但异宽窄写/宽读、端口模式和初始化必须得到实际映射支持，不能承诺直接变21 RAM |
| DSP双路INT8打包 | 当前首要瓶颈是XLR/布线而非125/160 DSP；打包/符号修正可能增LUT与路由。待主要瓶颈缓解再验证，不先宣称DSP减半 |
| 关闭CPU乘除或调试 | 可能省资源，但改变CPU ISA/软件构建或调试能力；先做官方Lite保功能配置，再考虑这些取舍 |
| 减MAC数/减少outstanding/缓存槽 | 直接触及吞吐，不作为资源优化默认方案 |

尤其不能把23.315fps@150MHz当成当前100MHz联合工程的余量：**仅在周期数完全不变的假设下**，旧最慢6,433,652拍在100MHz才约15.543fps，距15fps预算仅约3.50%；这不是100MHz整机实测，真实DDR/CPU和CDC可能改变周期数。

## 6. 执行与验收顺序

1. 独立量化窄舍入候选：逐拍仿真→同约束叶级综合→确认实际资源/时序收益；失败即保留原版。
2. 独立Sapphire S1/S2配置：实际生成→新公开端口/配置审查→MAP层次对照→选定后接入C38候选；不能用行为CPU综合作为官方IP资源结果。
3. 将有效优化联合PNR，先争取路由收敛及明显余量；在失败分支也保留紧凑层次/时序摘要，避免临时目录清理后只剩错误信息。
4. 仍不足再做操作数/窗口重构，而不是继续在旧高占用工程上反复换seed。
5. 恢复真实时钟/DDR假设下的数值与吞吐回归，最后加入活动视频外壳、完整CDC、peri/pin及板测。不能靠删功能或减约束把项目“优化通过”。

本轮未新启动Vivado或重型EDA，也未下载图片/大文件。仅一次官方网页查询核对Lite语义；所有分析均依据小型摘要及选定源码，本轮新文件不包含仿真临时工程。
