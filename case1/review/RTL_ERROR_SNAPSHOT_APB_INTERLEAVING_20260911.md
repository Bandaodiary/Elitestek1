# 故障诊断真实 APB 交错读取验证

本轮不改生产 RTL，扩展已有 IRQ/诊断 testbench。此前软件 mock 能证明
重试流程，RTL 单独事件测试能证明序号更新；本轮补真正 APB 传输期间的
交错，避免将两者直接当成完整读协议证据。

## 测试覆盖

按 sequence→code→address→sequence 发起四次 APB 读。在四个读取采样
沿分别注入新错误，并各跑同码/不同码两种模式，共 8 个交错场景。

- 新错误发生于前三次采样沿：前后序号不同，混合或已经过时的读取尝试
  被检测到；随后稳定重读得到新错误记录。
- 新错误恰在末次序号采样沿：APB 采到更新前的序号，code/address 也都
  来自更新前，仍是合法一致旧快照；下一次读取得到新记录。

这些检查在有效 APB 上升沿采样，不是延后到状态已改变的下降沿，也没有
force 内部状态。仍保留 1024 IRQ/W1C 组合和只读序号/清除/reset 检查。
定向 1 配置通过，runner 要求唯一 `C1_APB_ERROR_SNAPSHOT_PASS` 标记。

恢复接口 host 测试和旧驱动 host 测试也已重跑通过。它们与本 RTL 测试
仍是分别执行，不声称已经在 RISC-V 上运行 C 驱动。

## 全量回归结果

当前生产 RTL 全量 Icarus 回归退出码 0：
`C1_REVIEW_FIXES_REGRESSION_PASS configurations=598`。
此计数为 runner 配置数，包含预期失败的负向配置，并非 598 项独立功能。
本轮没有重跑整机 xsim/golden、Efinity 综合或板卡验证；此前整机结果
早于 ERROR_SEQUENCE 改动，不作为当前版本整机通过的证明。

## 适用边界

读取期间全局 reset、序号完整回绕、多个控制者无序访问仍不在一致性保证
内。序号不是错误 FIFO，不能保留每一条历史故障。软件 callback 必须
提供有序且已完成的总线读写，诊断一致不等同于诊断始终最新。
