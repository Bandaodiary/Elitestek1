## 1. 本阶段实现与保留范围

保留 C29 完整主机、C30 前端及所有旧生产基线，新增三个独立 RTL 文件：

- [c1_r2_camera_decimated_ingress.sv](../rtl/r2/c1_r2_camera_decimated_ingress.sv)：在 C30 像素对入口上增加固定整帧接纳相位，其余像素对打包、CDC、取消、源/AXI 排空逻辑不变。
- [c1_r2_video_rgb2_system.sv](../rtl/r2/c1_r2_video_rgb2_system.sv)：加入真实 VS/DE→规范像素对的 raster_source，用 C30 overlap Resize/Capture；仍与 CNN、CPU、双画面 scanout 共享实际 AXI fabric 和帧池。
- [c1_r2_rgb2_host_system.sv](../rtl/r2/c1_r2_rgb2_host_system.sv)：保留 CPU 多 ID 适配、APB16 本地窗口和 IRQ，透传新的双像素视频接口及接纳参数。

闭包为 **45 个生产源**，不是独立前端探针。C29 的执行器、参数精度、96 MAC 阵列、图编译包、AXI 信用和帧池均未改变。源派生门禁只允许上述连接、接纳相位和寄存器扩展的变化，见[源审计](../logs/r2_c31_source_gate_20260914_b.log)及[完整检查器](../golden/check_r2_rgb2_host_evidence.py)。Efinity 入口为[probe](../efinity/c1_ti60_r2_rgb2_host96.sv) / [XML](../efinity/c1_ti60_r2_rgb2_host96.xml)，仍不是含企业 CPU/CSI/DDR PHY/HDMI 的板级 top。

```text
RGB48 + 正 VS + DE/VALID，相机时钟约 70 MHz，不可回压
  → C30 raster_source（最后一对等下一 VS 确认）
  → C31 decimated_ingress（整帧接纳、ROI、49-bit FIFO）
  → C30 overlap Resize → RGBX32 Capture ─┐
  → C29 CNN/容量优化执行器 ──────────────┤

APB16/IRQ → 原控制与帧池 + 新 R2C2 相机只读扩展
```

## 2. 整帧接纳与软件 ABI

`FRAME_DIVISOR` 为构建时参数，默认 2，RTL 允许 1..256。源域相位在**每个规范 SOF** 上前进，包括忙或禁用时；仅相位 0 且空闲/启用时才接纳。协同复位后的第一个源帧是相位 0。仅跳过整帧，没有帧内 ready，也不通过逐帧 reset 清 FIFO。

目标源周期为 1,196,052 个相机时钟，名义 70 MHz 下约 58.53 fps；除数 2 的接纳机会约 29.26 fps。忙/禁用仍可能额外跳帧，因此这不是实际采集或 CNN 帧率保证。保留源帧编号作为 tag，例如除数 2 时为 0、2、4……，不是重新编号为连续采集序号。

| 本地 APB 偏移 | C31 含义 |
|---|---|
| `0x80` | 相机扩展标识 `0x52324332`（R2C2），与旧 R2C1 区分 |
| `0x90` | FIFO 峰值，单位为 49 位像素对/单尾记录，不是标量像素 |
| `0xB4` | FIFO 深度，同样以记录计；当前 512 |
| `0xB8` | `0x01310201`：能力版本 1、记录宽 49、每记录最多 2 像素、单位代码 1 |
| `0xBC` | 构建时 `FRAME_DIVISOR`，只读 |

旧 R2V2 核心页及 R2H1 的 `0x100..0x108` 主机页不变；新增相机页共 48 个正/负 APB 探测，包括写只读寄存器、未对齐地址和高位地址别名拒绝。`seen` 包括所有规范 SOF，`skipped` 包括相位跳过和忙/禁用跳过；最终 lease 完成仍只由 `camera_result_valid && camera_result_admitted` 驱动，不能提前使用 Capture 内部 done。

新软件[只读能力 API](../software/include/c1_r2_rgb2_camera.h) / [实现](../software/src/c1_r2_rgb2_camera.c)拒绝旧 ABI，不写相机寄存器，不宣称读取原子实时快照。主机 C 测试覆盖 256 个合法除数、9 个错误输入/能力/配置情况，错误时输出不变；另用已安装 Efinity RISC-V 工具链成功编译 RV32IMC/ILP32 对象，核对 ELF32 和 MMIO fence，见[测试结果](../logs/r2_c31_camera_software_20260914_b.log)。对象立即清除；这些测试不是 Sapphire BSP 或实际板载 CPU 运行结果。

## 4. 小图密集源失败：保留的容量边界

初始 `c31_rgb2_matrix_20260914_a` 在 32×32 配置下真实 FIFO 溢出（错误码 2），失败记录保留。该缩小测试的源为 68×68、ROI 为 64×64，水平消隐仅 4 个相机周期；ROI 占源宽 94%，而目标 1080p 的 ROI 占源宽 75%。两行 Resize 在行加载/采样交接期间积压，这种密集行突发不能由当前 512 记录 FIFO 全部吸收。

最终**小图功能配置**把既有消隐重新分布到各行：`HBLANK=WIDTH+4`，相应减少垂直空闲，**不改变源帧周期、两个时钟或整帧接纳频率**。保留 `CAMERA_BLANK_OVERRIDE=4` 可复现密集突发压力；不声称该压力配置已被 RTL 修复。

**原生配置未降低负载**：仍固定 106 个相机周期水平消隐、前 46/后 60、1080 有效行、垂直 20/2/20 行及 1,196,052 周期/帧。其完整 CNN 共享 DDR 结果必须单独完成，不能从小图 PASS 外推。若真实目标下仍发生溢出，需要继续调整行缓存/调度/带宽；不能仅靠修改测试波形宣布问题解决。

吞吐风险也必须保留：c 尾日志中最后一笔 CNN 为 **10,508,274 个核心周期**，即便不计帧间调度，也超过 150 MHz 达到 15 fps 所需的 10,000,000 拍预算。这不是可发布的稳态帧率，且 CPU 流量覆盖未通过；后续需要真实全负载复验及针对阶段停顿的优化，不能继承 C26 的帧率。

### 6.2 周期差异定位与公平比较边界
