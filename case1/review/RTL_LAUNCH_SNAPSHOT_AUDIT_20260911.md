# START 配置隔离与寄存器生效边界复核

## 本轮结论

未发现本次检查范围内的生产逻辑缺陷。扩大控制器的配置污染测试，并修正
CSR 源码注释中“所有配置均下次启动生效”的过宽表述；未改变硬件行为。

`tb_c1_r1_soc_control` 的 WRITE_REGION_CASE=39 原来只修改权重地址。
现在在 START 已接纳、参数加载请求被背压时，对以下 12 个输入字段整体
按位取反，保持 5 个周期：连续模式、丢帧模式、宽高、输入/输出格式、
输入/输出表基址、描述符基址、权重基址、描述符数量、tensor 基址。

测试检查对应 346 位内部快照完全不变，静态地址检查仍合法，参数请求与
地址保持正确且没有错误事件。恢复 shadow 输入后继续执行原场景。
普通/注册 fatal ticket 两种模式均输出扩展 PASS 标记；控制器定向回归
172 配置通过，退出码 0。runner 对场景 39 增加完整标记门槛。

这不是经过真实 APB 写入的 CPU 联合仿真，也不覆盖整个任务期间所有更新
相位或下一次启动装载新值。本测试直接驱动 lifecycle controller 输入。
独立输入几何、resize 系数由既有测试覆盖，不属于新增的 12 字段。

## CPU 集成必须区分的生效契约

| 类别 | 当前连接与行为 |
|---|---|
| 任务配置 | `c1_r1_soc_control` 在接纳 START 时锁存消费的配置字段 |
| 系统使能与取消命令 | 是实时控制，不属于只影响下一次任务的 shadow 数据 |
| 显示模式 | `c1_r1_display_subsystem` 经 CDC 传递，并在视频帧边界锁存 |
| input/output stride、style ID CSR | 当前 `c1_r1_portable_soc` 中只见 CSR 输出连接，没有直接传给任务控制的数据通路消费者；不能据寄存器可读写推断功能有效 |

后续软件接入应依据实际任务描述符、缓冲描述及模型加载契约设置参数；
不要通过增加第二套 live stride/style 路径绕过既有任务快照。若需要使
这些 legacy CSR 真正控制数据通路，应另行定义优先级和启动原子性后实现。

本轮没有重新执行全量 598 配置、整机 golden、Efinity 或板测。
