# Resize CSR 启动快照贯通

## 实现

`c1_r1_soc_control` 增加默认关闭的 `CONFIGURABLE_RESIZE` 参数，以及四个有符号 Q16.16 配置输入和对应 boardless 输出。接受系统 START 时，横纵步长及初相位与其他任务配置一起锁存；关闭参数时仍使用单位步长、零初相位，不读取新输入。

完整 `c1_r1_portable_soc` 为控制器启用此参数，将 CSR 0x064、0x068、0x06c、0x070 接入控制器，再将锁存输出接入 boardless 的 `job_*_q16`。不再硬连单位映射，也不将实时 CSR 值直接用于运行中的任务。

双行 Resize 缓存要求纵向读取不倒退，因此 `job_config_legal` 增加锁存纵向步长非负检查。负纵向步长沿用任务配置错误 0x12，在参数加载/采集/CNN 启动前拒绝。零步长允许；负横向步长与有符号初相位允许，边界裁剪由已有 Resize 实现负责。没有增加动态除法器。

源尺寸寄存器 0x060 仍未连接完整 SoC 的采集配置；源/目标同尺寸约束尚未放宽。其他旧 top wrapper 仍可能只提供寄存器存储，没有这里的启动接线。软件头文件已区分这些边界。

## 验证

控制器异尺寸测试启用可配置 Resize，启动时传入 x_step=-1.5、y_step=2.0、x_phase=0x7fffffff、y_phase=-0.5，然后立即改写实时输入。boardless 启动时逐项检查原快照，旧模式仍检查单位映射。非法配置测试由四个源尺寸案例扩展为五个，新增负纵向步长，要求不发出参数/采集/boardless 启动且只报错一次。

同尺寸/异尺寸、直接/寄存故障通知四种控制器配置全部通过。此处源/目标与 Resize 参数是控制接口契约测试，不是这些极端参数对应实际神经网络图像质量的证明。

全量 Icarus **123 配置符合预期**（包括预期失败检查），本轮扩展既有控制器配置，未增加配置计数。

完整 SoC Icarus 编译/展开通过：128 源文件，0 errors，603 条工具诊断；没有新增综合或时序结论。

为整机兼容性回归，数值 testbench 在接受 START 后、送摄像头帧前，通过 APB 写四个与原配置不同的值，其中纵向步长为 -1；读回证明影子写入生效，并检查 boardless 命令仍为已接受的单位映射。随后将影子值恢复默认供未来任务使用。数值回归继续核对真实 CNN、DDR 与两路显示。

实测 `review_resize_csr_snapshot_20260910` 已 complete，73.094 秒，日志包含 `C1_NUM_RESIZE_CSR_SNAPSHOT_PASS busy_writes=4`。Python `--require-video` 核对彩色 RGGB 的 64 输入、22 stage/836 C8 输出、64 DDR 像素和原图/处理图各 64 显示响应，全部通过。安全脱离 Windows Job 启动，临时工程目录已确认删除，仅保留约 54 KB 精简日志。
