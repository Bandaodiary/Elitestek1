# 大图预览：Resize 后无损分流基础

## 当前瓶颈与接入方案

现有显示只能完整消费各自 640×480 以内的图像，而采集帧可能大于该范围。直接放宽显示尺寸校验会使未消费的行列阻塞双行缓存，不能解决预览。

可复用现有 Resize 结果建立独立“风格网络前预览”帧：Resize 后的 centered-C8 流同时送 CNN 和预览写入器，预览恢复 RGB888 后写入尺寸受控的 DDR 缓冲，再由现有 display reader 显示。这里的预览是缩放后的未风格化图，不等同于当前“原图”路径所读取的完整采集帧；后续应以显式模式启用，保留旧显示语义。

## 新增 RTL

`rtl/video/c1_r1_preview_fork.sv` 实现一个有寄存的双消费者分流节点：

- 99 位共享 token 保存 C8 数据、x/y 和 SOF/EOL/EOF，两个 pending 位分别记录 CNN/预览尚未接收；
- 快支路完成后撤销自己的 valid，慢支路继续看到稳定数据，不会重复接收；
- 只有两支路均完成（或本拍即将完成）才允许上游覆盖 token，支持同拍取出并替换；
- CNN 数据保持原样，预览按 lane0/1/2 的 R/G/B 顺序异或 0x80 恢复无符号 RGB888；
- 同步 rst 是任务流的破坏性清空，复位期间屏蔽所有握手，未接收的分支 token 被丢弃。

RTL 声明层面为 99 位 token 和 2 位 pending；未测量综合资源。寄存延迟一拍，双支路持续 ready 时设计可每拍接受一像素；这不是系统吞吐实测。

## 验证

`tb_c1_r1_preview_fork` 对两支路分别记分，检查 C8 全数据、RGB 转换、坐标和所有帧标记；对有效且被背压的 token 检查数据/valid 稳定。

实测 64 像素完整帧两路各接收一次，63 次同拍替换，CNN 先收 16 次、预览先收 10 次；覆盖预览初始 35 拍不 ready、后续不同周期背压。末像素另作长背压，检查 CNN 已接收 64 个、预览只接收 63 个时，busy 与带 EOF 的 preview_valid 必须保持，直到预览接受。四次取消分别覆盖仅 CNN 已接收、仅预览已接收，清空后恢复，无旧 token 重放。定向 PASS，已加入默认 Icarus 回归。

完整 SoC 编译/展开通过（129 源文件、0 errors、603 条工具诊断），但该新模块**尚未在 SoC 中实例化**；这项编译不证明预览已经集成。

全量 Icarus **125 配置符合预期**（包含预期失败检查）。补充末像素长背压检查后，新模块定向测试再次通过；本轮临时镜像/向量已清理，无波形保留。

## 必须继续完成的集成条件

1. 在 boardless 的 descriptor dispatch 屏障后接分流，默认关闭预览时保留旧路径；取消与该任务的 stream flush 一致。
2. 预览写入器、DDR 地址/stride 和缓冲所有权需要明确且不得与原始采集、处理输出或 tensor 区重叠；缓冲可按现有输入索引跟踪，但不能由临时地址猜测。
3. 完成条件不仅是 fork 不 busy，还必须包括预览 writer 所有已接受 AXI 写的 B 响应退休。失败/取消也必须先排空外部事务，不能仅清空 fork 就释放帧。
4. 正常显示切换仍在帧边界提交与任务对应的预览/处理图；新增预览模式不能默默改写旧“原图”golden 的含义。
5. 添加真实 DDR 提交、支路长背压、写响应错误、取消及显示恢复的整机数值验证，再评估大图和吞吐。

本轮仅交付可验证的分流基础，不宣称大图预览完成，没有新增综合、xsim 或板测结论。
