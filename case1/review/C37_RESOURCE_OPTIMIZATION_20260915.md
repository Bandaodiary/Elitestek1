# C37：四项 RTL 资源优化开发记录

日期：2026-09-15。状态：**四项RTL优化已完成并验收**。单元/逐拍回归、同模型PNR对照、三模型整机矩阵/原生小图及稳定Mosaic的640×480六帧原生吞吐全部通过；实际工具已退出，私有仿真工程已清理。C37独立工程可作为后续集成的资源优化版本，C35/C36源码与历史证据保留不覆盖。下文各时间点为开发历史，最终结论见末节。

## 目标与边界

完成四项优化：row1/2 行缓存容量、宽请求与参数传递、Resize 等价算术、24/48 通道容量参数化。保持 96 MAC、INT8 权重/累加/量化规则、CPU/AXI ABI、行融合所有权。不是重新训练模型，也不包括 DSP 双路打包。

基线：C35 PNR 44,352 XLR / 129 RAM / 130 DSP；C36 稳定 Mosaic 在约 30.43 fps 采集压力下的六帧仿真最慢 23.319344 fps@名义150MHz。两者不等同于新候选资源/吞吐或板级成绩。

## 实现路线

- `rtl/c37/` 保存同名模块的独立替代源；一个工程不能同时编译候选与同名基线。基线源码不修改。
- row1/2 使用参数 `ROW_WORDS=512/1024`，保留 row0 的 8×512×32 分区共享 RAM。当前执行图各空间层每银行最大320地址；新增容量拒绝与边界验证。
- 请求携带通道索引；参数表在整个算子租期不可写。独立量化参数解析级避免把索引选择直接接到乘法临界路径。保持参数 FIFO 深度8和完整在途计数。
- Resize 采用 `p0*4096+(p1-p0)*w1`；保持两次 +2048/Q12 舍入和四级弹性流水。
- `MAX_CHANNELS=24/48` 控制真实偏置/量化参数存储数量；权重字加载 ABI 与六路 SRAM 读带宽不变。

### 已解决的开发问题与性能边界

1. 第一次沙箱编译遭遇临时目录ACL清理问题；改为普通权限的受限负载短运行后正常清理，原指定空目录也已确认并删除。没有保留仿真工程或波形。

3. `fallback a` 数值未报错，但旧测试的固定流水延迟断言失败：868拍对原867拍。新增参数解析级本来就增加1拍。独立 `tb_c37_operator_fallback.sv` 仅更名、调整**精确固定延迟+1**及标记；所有数值、MAC拍数、持有、复位和所有权检查均保留。ST0随后187作业精确周期通过；ST1也全部通过。不是把错误宽松化为任意周期范围。
4. 新FIFO逻辑记录为59位（tag16+mask6+channel36+residual1），不是初步估算中未计残差标志的58位；源码存储位不等于实际FF。原1902位请求改为1597位，偏置按请求索引读取，量化按退休记录索引解析；参数表保持整算子租期不变。
5. 新解析级不改变归约MAC拍数/连续吞吐，但增加算子固定一拍，尚需原生多帧测量整体影响；不能由8×8测试的12,618拍间隔外推全帧fps。
