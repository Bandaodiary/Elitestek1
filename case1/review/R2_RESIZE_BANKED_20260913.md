# R2-C23：紧凑Resize缓存与平台接入边界

日期：2026-09-13。本轮完成独立 Resize 候选和验证，**没有把 Resize 接入 C22 主机或实际摄像头**。R1、C18、C21、C22 的生产源全部保留；当前CNN/主机候选仍是C22。

最终证据门禁：[r2_c23_gate_20260913_b.log](../logs/r2_c23_gate_20260913_b.log)。a也通过；b进一步逐字检查负控尺寸/背压组合，防止通用数字解析器把`8x8:4x4`只解析成8。本轮没有新增CNN帧率结论。

## 1. 结果与资源边界

| Ti60F225 I3，单独Resize探针 | XLR | RAM | DSP | 150 MHz setup / hold（ns） |
| --- | ---: | ---: | ---: | --- |
| 原R1，输入/输出尺寸与Q16相位可变 | 2,398 | 20 | 18 | +1.469 / +0.044 |
| C23奇偶银行，相同动态配置 | 2,558 | 12 | 18 | +0.963 / +0.044 |
| C23奇偶银行，输出固定640×480、输入/相位可变 | 2,413 | 12 | 18 | +1.348 / +0.091 |

所有探针均 `MAX_WIDTH=2048`、`REGISTER_ABORT_RESET=1`，使用相同原有插值算术。对应运行分别为 `c23_resize_reference_i3_20260913_a`、`c23_resize_banked_i3_20260913_a`、`c23_resize_640_i3_20260913_a`；都是实际 map+PNR，不是估算。

同配置动态版本节省 **8/20 RAM（40%）**，代价是增加160 XLR、setup裕量减少0.506 ns。不能把逻辑存储容量减半直接写成物理RAM也减半：Efinity对原4个2048×24位RAM共用了20块，对新4个1024×24位RAM用了12块，存在端口/位宽碎片。

固定640×480输出是赛题目标下的另一个综合配置，不是通过删去输入/Q16配置人为缩小功能；它不替代动态版本的同条件对照。该探针仍是单独Resize，不是整板设计，不保证实际板级150 MHz。

## 2. 架构改动

原 `c1_r1_resize_line_sampler` 为同时取 `x0`、`x1`，把每条完整RGB行复制两份。双线性坐标生成器实际始终满足 `x1=x0+1` 或边界钳位后的 `x1=x0`，因此可用奇偶列银行读取，取消副本。

- [c1_r2_resize_pair_ram.sv](../rtl/r2/c1_r2_resize_pair_ram.sv)：两条行缓存各分奇偶银行，共4个半深度、24位SDP RAM。请求拍按列奇偶路由地址，奇偶选择位同步寄存；下一拍恢复两行、两列的四个RGB样本。边界重合时两输出选同一银行，不误用另一个银行的数据。
- [c1_r2_resize_line_sampler.sv](../rtl/r2/c1_r2_resize_line_sampler.sv)：保留原行有效位、行标签、保留/丢弃、单在途响应、栅格检查和错误状态机，只替换RAM组织，并把横向非相邻/反序坐标加入可综合的 `ERR_REQUEST_PAIR=4` 检查。
- [c1_r2_resize_pipeline.sv](../rtl/r2/c1_r2_resize_pipeline.sv)：只替换sampler类型。原 `c1_r1_resize_system`、`r1_resize_request_q16`、`r1_bilinear_interp_rgb888`、有符号48位相位累加、Q0.12系数及两级舍入均未改。

原独立sampler支持任意横向两点；**新独立sampler不再支持任意两点**，只支持相邻/重合。这个限制不缩小现有完整双线性pipeline的配置集合：即使负X步进、极端相位或边缘钳位，生成器的每对样本仍满足限制。若未来用该sampler做任意采样，必须换回原模块或重新设计端口。

不复位SRAM，只复位有效状态和流水。输入、输出遵守ready/valid；输出EOF必须等源栅格完整排空。局部abort会阻止同拍外部握手并清空内部流水，下一任务必须从源(0,0)重新开始；它不是已提交DDR事务或主机frame lease的取消接口。

源码检查器直接对照旧/新wrapper和原测试台，sampler差异限于RAM替换和横向坐标守卫；C22整套源码门禁同时重新通过。没有改正在进行C21/C22原生仿真的源闭包。

## 3. 数值、边界、恢复与吞吐证据

### 保留的小图回归与跨模拟器

Vivado运行 `c23_resize_xsim_20260913_a` 使用注册abort reset，8.116秒，同11配置/207输出与末尾恢复检查通过；[result.log](../logs/r2_resize_xsim_runs/c23_resize_xsim_20260913_a/result.log)。WMI worker经运行时检查不在Windows Job中，无波形，私有仿真工程已清理。

### RAM与硬件错误路径

[r2_resize_ram_20260913_b.log](../logs/r2_resize_ram_20260913_b.log)：宽度1、1025、2047、2048，10,786次四点读取、10,754次写入、10,786次保持、32次暖复位；包含完整地址空间、奇数末列、相邻跨银行、同点钳位、随机稀疏写和复位期间读写禁止。参考为独立完整行数组，不复用被测银行映射。

4项helper负控拒绝非相邻、反序、读/写越界；另直接驱动sampler验证2种非法横向请求产生硬件错误码4、停止流和保持busy，随后通过复位恢复并正确读取相邻/重合样本。不是只靠 `ifndef SYNTHESIS` 断言证明错误处理。

### 旧/新实际RTL逐周期对照

[r2_resize_miter_20260913_a.log](../logs/r2_resize_miter_20260913_a.log)：1×7→4×3、2047×5→641×3、2048×5→640×4，各背压0/1。旧、新实际pipeline接同一输入/背压，每拍比较源ready、配置ready、valid/busy/done/error及输出数据和坐标/帧标记；另与独立Python双线性golden核验，共8,990输出。两个被破坏golden的负控均被检出。

[r2_resize_1080_20260913_a.log](../logs/r2_resize_1080_20260913_a.log)：完整 **1440×1080→640×480**，1,555,200个实际输入和307,200个输出逐像素正确，新旧均 **2,477,887拍**，约16.519 ms@150 MHz。所有源像素都通过公开流接口进入，没有直接填充DUT行RAM。源图为确定性RGB合成图，不是摄像头实拍；本次不含前级裁剪实现。

这次完整测试允许源停顿，测得源回压920,762拍、最长连续1,921拍。故不能把约16.52 ms说成真实摄像头无丢帧证明，也不能把Resize模块的处理时间说成CNN/整系统帧率。原摄像头不能无限回压，FIFO/CDC必须结合实际像素速率、行消隐、裁剪相位和最坏等待重新验证。

最终检查器另拒绝3项证据变异：读延迟、取消次数、周期一致标志。所有完成的Icarus临时向量/可执行文件均已自动清理。

## 4. 更新后的平台预算：还没有闭合

C22联合核心是134 RAM / 41,252 XLR / 112 DSP；官方现配置CPU/DDR/CSI/Debayer粗和为105 RAM / 17,361 XLR / 4 DSP，依据见[C20容量审计](R2_WEIGHT_MEMORY_BUDGET_20260913.md)。只选择一套DDR控制器，不叠加视频与SoC两套。

| 跨工程预算 | RAM / 256 | XLR / 60,800 | DSP / 160 |
| --- | ---: | ---: | ---: |
| C22＋上述平台，未加Resize | 239 | 58,613 | 116 |
| 再加原动态Resize | 259 | 61,011 | 134 |
| 再加C23动态Resize | 251 | 61,171 | 134 |
| 再加C23固定640×480输出Resize | 251 | 61,026 | 134 |

新缓存消除了这份粗预算的RAM超额，但只余5块，且固定输出配置的XLR仍超226。新增CDC、输入FIFO、ROI裁剪/坐标转换及取消接口未计入，不能宣称“全部放得下”。这些数值包含两个独立探针的观察/配置外围，又采用跨工程层次资源相加；联合综合会改变packing与可裁剪逻辑，因此也不能据此断言芯片一定装不下。

下一步必须做真实联合源闭包和控制/数据连接，用联合层次报告检查重复缓存、外围观察壳和平台可选外设，而非继续用单模块资源拼算代替整机实现。PLL/Clock Mux配置和物理CDC仍另行审计；官方视频工程时钟资源已用满的问题未解决。

## 5. 与官方例程联合开发的下一步

1. 以SC431现有1920×1080配置为入口候选，明确RGB端居中裁剪1440×1080以保持4:3；裁剪在Debayer前还是后会影响Bayer相位，不能直接裁RAW字节后沿用旧相位。此轮只验证了已裁剪RGB的Resize。
2. 加入相机域到核心域的有限缓冲和栅格检查，验证不可回压输入下的水位/溢出。所有异常帧必须整帧丢弃并从下一SOF恢复，禁止补假像素伪造完整图。
3. 将Resize配置接纳与C22 capture lease接纳绑定；Resize错误/取消必须使capture、在途写事务和帧所有权一起安全排空。现有Resize的局部abort不能替代这个系统合同。
4. 完成Resize→C22实际主机的数值、错误与连续帧测试，再联合官方CPU/DDR接口生成工程，检查真正的资源与时序。当前C21/C22原生六帧仍由原worker运行，最终性能需各自独立门禁，不继承旧版结果。
