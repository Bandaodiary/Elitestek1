## 1. 修改内容

| 审查项 | 修改与当前状态 |
|---|---|
| R1：AW→W 死锁 | 修复共享 N 路、旧双路和多 outstanding 写候选三个仲裁器。选定 owner 后独立推进 AW/W，单事务仲裁器分别记录地址完成与最后数据完成，B 结束才释放。写候选根据已接受 descriptor 选择 W owner，不再等待下游 AW 握手。已定向验证。 |
| R2：RLAST 错误掩盖 | 共享仲裁器增加独立 `rd_skid_terminal_q`；上游 RLAST 保留总线原值，owner 结束条件另存。长度与 RLAST 不一致时返回 SLVERR，已有 SLVERR/DECERR 不被降级。direct/skid 两种路径均按相同规则报错。已定向验证。 |
| R3：CNN/显示互斥 | 增加默认关闭的 `CONCURRENT_DISPLAY_PREFETCH`；开启时允许显示补给与 CNN 任务重叠，保留新 pair 的所有权屏障。要求启用 display response FIFO 且每路至少 64 个像素容量；本轮测试深度为 128。双帧实际观察到 48 次显示读地址握手与 job 重叠，但仍有欠载，故只作为候选。 |
| R4：15 fps 结构瓶颈 | 本轮通过并发补给和独立 AW/W 消除部分序列依赖；没有宣称解决 tensor 重复读取、全局 outstanding 或 MAC 利用率瓶颈。下一步仍需按层测字节量、缓存命中和等待周期。 |
| R5：综合探针 | `observe` 与 `observe_keep` 改为 47 bit；descriptor 索引不再固定零。descriptor、参数和窗口分别支持串行加载独立数据，加载期间关闭对应事务 VALID，减少原探针的重复输入折叠。独立装载测试通过。旧 435.540 MHz 报告不适用于新探针，尚未重新 P&R。 |
| R6：CDC | Gray 指针同步级与 reset 同步链增加 ASYNC_REG 标记；FIFO/reset 功能回归通过。属性是否被 Efinity 采用、Gray 总线物理偏斜与 EBR 映射仍须板级约束和实现检查，不能视为 CDC 物理签核。 |

RLAST 错误后的历史 ARLEN 终止策略保留，以便当前叶模块完成错误响应/排空；这不承诺恢复任意非法从机残余数据。若控制器出现多余拍或无法确认事务边界，应停止新任务并按系统级恢复流程处理，不能将错误直接清除后继续复用链路。

## 6. 追加修复：显示几何边界与响应有效性

`c1_r1_display_subsystem.sv` 原先将固定 640×480 compositor 的全部请求直接送入 line store；小尺寸图像的 x 坐标在端口切片后会回绕，y 也继续请求至 479。未选源的 drain 仅限制宽度，未限制实际高度。因而小尺寸 BFM 的欠载不能直接解释为 DDR 带宽不足。

本次修改：

- 在坐标截断之前检查完整 x/y 与已接受的 width/height；drain 同样限制高度。
- 保留 720p 和两个固定 640×480 面板布局，小图位于对应面板左上角，其余位置补黑，不隐式缩放。
- 使用 line-store 的同步 response_valid 选择 RGB，避免边界外继续输出上一像素的非零值；不屏蔽实际有效请求产生的 underflow。
- START 握手时锁存几何，再同步到 pixel 域，避免未接受的软件配置变化影响活动事务。此项是逻辑层 bundled-data 改进，不替代物理 CDC 约束。

新增 `tb_c1_display_geometry.sv`：注入 raster 和一拍响应，检查 4 种模式、8×8/640×480 尺寸、水平/垂直边界和响应对齐；分别以 640 与 8 的 line-store 宽度执行，共 199,680 个采样点。小图每路恰好请求 64 次，并验证未接受配置不改变活动几何。此测试有意替代外部 raster/存储响应，不能独立证明 AXI 或实际 line-store 正确。

验证：`C1_REVIEW_FIXES_REGRESSION_PASS configurations=18`；127 文件顶层编译 errors=0、warnings=597。真实 line-store 测试通过 3 行/12 像素、忙银行写保护，以及 1 次预期欠载报警，确认报警机制没有被整体屏蔽。

默认配置整系统单帧 `geometry_fix_base_20260910` 通过（75.998 s），AW/W/B=852/868/852，AR/R=1119/2199，完整临时工程已清理。

并发双帧首轮 `geometry_fix_20260910` 在测试观察上限处失败：50 ms 等待结束时，第二次计算和 swap 已完成、读通道空闲，两个 FIFO 各余 48 个像素，720p raster 位于 y=41，需等下一合法图像窗口。修复前越界请求会错误地提前消耗这些数据。将小图 testbench 观察上限从 50 ms 调为 100 ms 后，以 `geometry_fix_v2_20260910` 复测；硬件 QoS deadline 仍为原先 1,000,000 cycles，完成/排空断言保持不变。首轮失败摘要保留，不作为通过证据。

复测 **整体状态仍为 failed**，不能只引用日志中较早出现的 TWO_FRAME_PASS：双帧功能部分完成（done=2、swap=2、drop=0、descriptors=44、new_done=2、monitor_frame=2），但末尾的实际重叠覆盖断言失败，`concurrent_display_ar_count=0`。该断言未删除或弱化。历史修复前的 48 次重叠已不能作为合法图像请求下的并发效果证据，需重新设计能够在 CNN 活动期间持续提供合法显示需求的测试。

该次运行完成边界的 QoS 实测为：`underflow=0`（修复前为 2）、`deadline_miss=2`、`last_frame_cycles=5197276`、`protocol=0`、`overflow=0`。这些是失败运行中已检查到的局部结果，不代表整个并发回归通过，更不能外推 native 15 fps。运行摘要见 [双帧复测状态](D:/contest/2026FPGA/yilingsi/case1/logs/portable_soc_cache_ddr_bfm_runs/geometry_fix_v2_20260910/status.json)。本次三个 xsim 运行的完整临时目录均已清理，仅保留小型日志和状态。
