# 可综合 RAW 光栅校验模块

日期：2026-09-11。

## 实现范围

新增 `rtl/video/c1_raw_raster_guard.sv`，将固定尺寸、逐行 RAW10 输入完整性检查实现为可综合逻辑，而非仅存在于 `ifndef SYNTHESIS` 的断言。

每次通过 start_valid/start_ready 启动一帧。坐标计数仅在合法 token 实际握手时推进，核对 x/y 顺序、首像素 SOF、行尾 EOL 与最后像素 EOF。正常 token 零缓冲透传，继承下游背压；数据与全部标志一起传送。

错误 token 不向下游呈现 m_valid，即使下游不 ready 也可在输入侧本地消费并锁存错误。错误后保持 busy、关闭 start_ready/s_ready/m_valid，直到显式 cancel 或 reset。第一错误码优先级为：1 坐标、2 SOF、3 EOL、4 EOF；这些是新模块内部码，尚未分配到现有捕获 CSR ABI。

最后一个正确 token 只有在实际被下游接受后才产生 done。cancel/reset 撤销本地传输资格并清空校验状态；该 cancel 契约仅适用于本地可丢弃流，不能用于撤销已呈现的 AXI VALID。

## 定向验证

`tb_c1_raw_raster_guard.sv` 运行 1×1、4×3、5×2 三个尺寸，均通过：

- 正确帧逐像素数据、坐标、帧标志及完成时机。
- 每个正常 token 人为背压三个周期，接入跨周期 ready/valid 保持检查。
- x/y 错位、缺 SOF、重复 SOF、错误 EOL、提前/缺失 EOF；错误期间下游保持不 ready，坏 token 仍被本地截住。
- 错误 sticky 持续、取消后重新传送完整帧。
- 已呈现且被阻塞的正确 token 在 ready 返回同时被 cancel，不得产生握手或 done，之后可重新启动。

三组分别完成 9/10/10 个正确帧与 7/8/8 次错误测试（1×1 没有第二个 token，不执行重复 SOF 场景）。统一回归入口新增 3 配置，本轮仅执行该定向入口，未重跑全量。

## 尚未接入 ISP 的原因和接入要求

这个模块目前是独立候选模块，未在 capture frontend 实例化，也未修改板级工程显式源清单。不能声称现有整机已经具备硬件光栅错误隔离。

截住错误 token 不会撤回此前已经进入 ISP 的合法前缀；若直接取消校验器并放行下一帧 SOF，ISP 的旧帧可能尚未结束。整机接入必须同时完成以下契约：

- 将错误映射为捕获故障，禁止坏帧完成/发布，并处理已经交给 writer 的数据与 AXI 事务。
- 为 ISP 建立局部帧状态清理方式，明确配置和 Gamma 内容是否保留/重装，不能擅自重置共享总线或相机 FIFO 的单个时钟域。
- 原始流重同步：继续丢弃至合法边界时不得把下一帧的 SOF 无条件消费掉；源永久停止时需要显式停止确认与协调复位政策。
- 重新启动校验器必须由上述恢复完成条件驱动，不能只根据 error 清零或本模块 busy 下降。

模块不检测合法 token 之间的无限暂停，不保证上游违反 ready/valid 后仍能保持下游稳定，不覆盖模拟 X/Z 或物理 CDC 问题。默认尺寸为 642×482，但本轮不是原生分辨率性能测试。

本轮不启动 xsim、综合或板测，不生成波形；临时编译文件和向量由脚本清理。最近整机回归证据仍为此前 458 配置，不作为本模块已集成的证据。
