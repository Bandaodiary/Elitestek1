# 写响应瓶颈：流水化与 packing 组合实测

## 运行与功能验证

固定 DW 权重缓存、MAC 预取重叠开启，与此前 profile 场景采用相同训练
工件、gray 12×10→8×8 输入及故障/背压设置。新增两项独立运行：

- `apb_engine11_writepipe_20260911`，worker 43828：仅新增 PipelinedResultWrites。
- `apb_engine11_writepack_20260911`，worker 46304：另加 TensorPackedWrites、TensorWriteEnd。

两项最终 complete/done、exit_code=0；分别通过要求 APB 恢复、延迟源确认
的完整 golden：22 阶段、836 C8、64 DDR 像素、120+64 显示像素匹配；
RAW timeout 0x46、64 周期 B 延迟、32 周期源停止确认、一次 flush、无
全局 reset 恢复正确。两个临时仿真目录均已确认不存在。

## 成功任务 job=2 的核心周期

| 统计 | 原写通路 | 写流水化 | 写流水化 + packing/end |
|---|---:|---:|---:|
| elapsed | 71826 | 71363 | 65670 |
| ST_WRITE_RSP | 28859 | 14310 | 19913 |
| 请求背压 | 1926 | 14941 | 1923 |
| 结果背压 | 12233 | 3940 | 120 |
| 逻辑 tensor 读/写请求 | 3620/836 | 3620/836 | 3620/836 |
| 整段仿真 AXI AW/B | 874/874 | 874/874 | 628/628 |
| 整段仿真 AXI W beats | 924 | 924 | 767 |

原写通路引用 `apb_engine11_profile_20260911`。AXI 数量包含该仿真完整
场景，不是只属于 job=2；表中两种观察窗口不能混用计算平均事务延迟。

仅流水化减少 463 周期（约 0.64%），很多等待从 WRITE_RSP 转移到请求
端，不能据状态时间减半声称任务加速一倍。组合减少 6156 周期（约
8.57%），逻辑请求不变而物理写事务/beat 减少，结果背压明显下降。
状态、请求背压、结果背压有交叉重叠，不应直接相加。

## 决策与剩余验证

这一组合值得作为下一优化候选，但本轮没有修改生产 RTL 或默认参数。
packing 与 end-marker 在第二项同时开启，尚不能分别归因；需补单独
packing 的对照，并检查尾包、奇数组数、非配对地址和取消时未满包的
行为。更大图像、计算阶段取消、目标 FPGA 时序/资源仍未验证。

即使全部关闭配置的同类小图是 73452 周期，本结果也不能按像素简单
外推为原生 640×480/15 fps。改进目标仍应围绕实际逻辑请求和缓存命中
服务开销继续量化，而不是仅增大 FIFO 或并行 MAC。
