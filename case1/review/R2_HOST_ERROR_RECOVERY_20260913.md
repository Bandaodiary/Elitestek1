# R2-C19：完整主机系统的响应错误、排空与恢复

日期：2026-09-13。C19 是对当前 C18 生产 RTL 的系统级验证补齐，**本轮没有修改或复制一套新的生产数据通路**。C18 原生六帧继续原进程，R1 和旧候选源码保留。

## 1. 验证的错误合同

每个正常测试执行四个 CNN 任务：先完成并实际显示一帧；在第二次任务中注入一个真实 AXI `SLVERR`；随后不复位，继续完成两帧并核对全部中间结果和显示。摄像头、CPU 流量代理及显示保持运行，首次短暂停止新 CNN 请求仅用于建立可保护的旧 FRONT。

| 注入模式 | 物理位置 | 必须观察到的行为 |
| --- | --- | --- |
| 1 | 参数读取的 R 响应 | 当前任务失败，不提交 stage 0，后续完整恢复 |
| 2 | stage 0 图像输入的 R 响应 | 当前任务失败，不发布不完整结果 |
| 3 | stage 0 写回的 B 响应 | 保持 B 后真实排空，失败层不提交 |
| 4 | stage 20 RGB 写回的 B 响应 | 即使部分输出已写入 RAM，失败结果也不能成为 FRONT 或被显示 |

错误由共享 AXI memory BFM 在响应通道产生，不是将 `nn_failed` 直接强制为 1。逐笔核验实际错误响应握手、所属 CNN master、stage、帧标签和响应码；完成时 CNN 的读/写债务必须为零。B 类测试额外保持响应，禁止在保留债务时完成。

只使能 IRQ bit 1（失败完成），先确认成功帧不会经此掩码触发 IRQ，再检查失败后真实 CSR 状态和标量 IRQ；最后验证 W1C、高页地址不混叠、成功计数不计入失败任务。bit 0 为成功或失败的 NN 完成，bit 3 才是需协调复位的 fabric/lease 错误，未改变既有 ABI。

正常 `SLVERR` 不要求 CPU 确认后才重新接纳新帧，因此错误 IRQ 的观察与下一次 START 可以同拍；但 START 必须在失败任务真实完成/排空之后。单纯删除这条时间顺序约束会失去保护，要求 IRQ 必须早一个周期则会错误拒绝合法行为。

## 2. 实际覆盖与证据

| 最终测试 | 配置数 | 成功 CNN | 预期失败 CNN | 失败后完整成功 | 正确显示像素 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 8×8，模式 1～4，背压 0/1 | 8 | 24 | 8 | 16 | 9,216 |
| 12×12，模式 3/4，背压 0/1，W 先于 AW | 4 | 12 | 4 | 8 | 9,792 |
| 128×4，模式 4，背压 1，至少两笔 CNN B 债务 | 1 | 3 | 1 | 2 | 5,120 |

这 13 个场景共 39 次成功、13 次预期失败，其中 26 次为失败后完整成功；均无显示欠载。失败标签从未成为 FRONT 或出现在实际显示完成记录中，读取所有者、golden 写结果、CPU ID 与实际共享 RAM 的检查全部保留。这里的四次任务包含一次预期失败，不能把每组写成四帧成功。

W 类小行场景保持 B **64 拍**，实测同一 CNN 主机在保持期间为 **一笔**写债务。128×4 条带的 RGB 输出行跨两个 16-beat burst，在保持 B **256 拍**时独立观察到同一 CNN 主机 **两笔**真实写债务；失败完成时两者已排空。该失败帧写入了 2,192 个 physical words，提交至 stage 19，FRONT 仍是先前 tag 0；之后两次完整恢复。系统总写峰值 7 与上述 CNN 两笔不是同一个统计，不能混用。

Vivado `c19_host_recovery_xsim_12x12_20260913_a` 重复最关键的 12×12/背压 1/W 先于 AW/末层 B 错误：25.195 秒完成，Job=false，私有目录已清理。三帧成功周期为 24,708 / 24,288 / 24,683，失败前后均用原 22 项模型。实际错误、完成、IRQ、采集、显示、CPU 等 **13 类事件**与 Icarus 同配置逐项一致；这是跨模拟器复核，不新增一个独立配置。

还运行四个真实模拟负对照：禁用物理错误，或屏蔽错误 IRQ，均必须被测试台拒绝；另有 14 个检查器变异被拒绝，包含删除真实错误/IRQ/显示记录、将真实完成时刻提前一拍，以及把两笔债务改成一笔或缩短保持时间。这些计数与正常错误恢复场景分开。

最终验收 `logs/r2_c19_gate_20260913_d.log` 与收口复核 `logs/r2_c19_gate_20260913_e.log` 均通过。入口：

- `sim/tb_c1_r2_host_recovery_system.sv`：实际 C18 host、共享内存、CPU/视频、错误和逐项数值监视器。
- `golden/run_r2_host_recovery_probe.py`：Icarus 矩阵，源闭包复用 C18 XML，私有配套包/向量退出即清理。
- `scripts/run_r2_host_recovery_xsim_detached.ps1`：独立 WMI 隐藏运行器，先确认不在 Windows Job 中，再启动 Vivado；无波形，自动清理。
- `golden/check_r2_host_recovery_evidence.py`：以真实响应/完成/显示时间线审计错误归属、排空、恢复、IRQ 和跨模拟器一致性。

首个 smoke 因 Icarus 对声明后引用的 unpacked array 无法绑定而编译失败；将测试台的注入逻辑移到数组声明之后解决，未改生产 RTL。初轮 a 日志保留，最终 b 矩阵补充了逐事件时间线；不将重复运行累计成更多独立场景。检查器开发中还修正了数字专用字段解析器丢失 R/B 文本，以及错误地要求 IRQ 严格早于下一次 START 的假设。

## 3. 修正旧检查器的完成时刻

C19 新增真实 `nn_complete` 握手时刻，发现既有共享时间线重建少算一拍。新旧 graph 均在 START 拍将 `frame_cycles` 清零，仅在 busy 且非 RESULT 状态递增；系统 lease 在拥有任务时持续允许完成。因此：

```text
实际完成握手 = START 时刻 + frame_cycles + 1
```

例如 xsim 首帧 START=1,750，内部计数=24,708，真实完成=26,459；故障任务 START=35,250，内部计数=23,459，真实失败完成=58,710，下一拍 58,711 同时观察错误 IRQ 和新 START。

`check_r2_rgbx_system_evidence.py` 已修正，并由本轮实际成功/失败握手逐个交叉核验。旧重建绝对完成时刻要加一，任务间 idle 间隔由两拍改为一拍；**相邻完成间隔的差值不变，15.3145 fps 和 2.0535%周期余量不变**。它不修改 RTL，也不是性能优化收益。

C12/C13/C14/C15 原生及 C18 局部验收均重新通过；新记录分别为 `r2_c12_c19_reaudit_20260913_b.log`、`r2_c13_c19_reaudit_20260913_a.log`、`r2_c14_c19_reaudit_20260913_a.log`、`r2_c15_native_gate_20260913_b.log`、`r2_c18_gate_20260913_c.log`。旧记录保留其当时计算方式；C12 初次复核 a 使用了错误的 PNR RunId，未通过物理验收，核实实际路径后 b 通过。
