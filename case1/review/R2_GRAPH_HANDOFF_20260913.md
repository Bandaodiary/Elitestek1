# R2-C6：完整图执行与真实张量交接

日期：2026-09-13。保留R1、C5及此前入口，新图执行器不替换默认SoC。

本阶段从独立算子行测试转向完整MicroStyle-24图：外部只初始化RGB输入与训练参数，
每层输出由RTL写入内存，后续层只能读取这些实际写回值。Python中间结果仅用于比较，
不再注入后续算子的输入。完整图执行不等于DDR/摄像头/CPU系统已经集成。

## 1. 新增模块及数据流

| 文件 | 职责 |
|---|---|
| `rtl/r2/c1_r2_microstyle_graph.sv` | 固定22节点拓扑、运行时尺寸/基地址、残差生存期、行调度与提交 |
| `rtl/r2/c1_r2_tensor_row_loader.sv` | 接收128位行传输，向C5参数/特征SRAM写入；读错误和非法参数排空 |
| `rtl/r2/c1_r2_tensor_row_writer.sv` | 六路结果并行散写到16个字节bank，转成128位规范行；等待写响应再完成 |
| `efinity/c1_ti60_r2_graph96.*` | 核级资源/时序探针，不是板卡引脚或DDR桥 |

内存读描述符 → 128位行装载 → **原C5共享算子核** → 六路行重排 → 128位行写回 →
写响应提交 → 下一行/下一层。仍只有一个96-MAC阵列及六路量化；本阶段未修改C5 RTL。

行重排缓冲为16×1024×8位逻辑存储（16KiB），每拍最多接收六个不同字节bank的结果。
PW、残差、encoder、DW和RGB的tag含义不同，由writer映射后统一，不将DW tag误当线性地址。
奇数行宽的尾像素及C3/C12的通道padding在输出端显式清零，不依赖旧RAM内容。

## 2. 内存合同：P2C8，不是R1或视频ABI

张量仍以HWC语义描述；物理上每个128位字包含一对横向像素的同一C8组：

`word_in_row = floor(x/2) * ceil(C/8) + floor(c/8)`

`byte_in_word = (x%2)*8 + c%8`

行长为`ceil(W/2)*ceil(C/8)`个128位字。所有行保持16字节对齐；padding为零。
输入帧每像素只有前三个uint8有效，loader执行`RGB-128`；最终输出也采用P2C8，前三
字节为RGB uint8。摄像头/视频端的RGB888/RGBX等格式转换仍需适配，不能直接连接旧帧DMA。

四个配置基址均要求8MiB对齐：输入一槽、工作区连续三槽、输出一槽、参数一槽。
硬件检查区域互斥和32位地址不绕回；每个槽的实际占用按形状计算，不代表片上分配8MiB。
支持4≤W≤640、4≤H≤480，宽高均为4的倍数。图拓扑固定，但尺寸、参数和基址运行时可变。

参数槽每逻辑stage保留8192字节，每128位字包含两条64位装载命令：
`{16'b0,kind[1:0],address[13:0],data[31:0]}`。kind只允许1权重、2bias、3affine。
Python从原训练arena重排，不制造新权重；实际参数传输2,333字，共37,328字节/帧。
参数仅在层开始时加载一次，行循环中复用。该命令映像不是原R1的16,896字节参数ABI。

可上传工件已生成于`model/r2_microstyle24_starry_functional/`，包含180,224字节的
`parameters.bin`及槽偏移manifest；实际使用字节仍是37,328。生成器
`golden/export_r2_graph_parameters.py`从原训练工件导出，检查固定拓扑和量化范围，
并与RTL回归的独立生成器逐字比较全部2,333个参数字。既有训练工件不修改，已有输出
不覆盖；`--verify`只核验现有导出。该映像将用于后续CPU/主机加载，不代表DMA已接通。

读写端口是**行传输描述符**，不是AXI burst。每个方向最多一个已接纳描述符；读数据
必须按序，`last`标记该描述符结束。之后的DMA必须拆分4KiB边界和硬件burst长度限制。
命令及输出数据遵守ready/valid保持；写端只有最后beat与写响应都完成后才释放该行。

## 3. 残差和虚拟节点

以下A/B/C表示工作区的三个8MiB槽，I/O为独立输入/输出区：

| stage | 输入 | 输出 | 保留的残差 |
|---|---|---|---|
| 0 / 1 | I / A | A / B | stage1的B |
| 2 / 3 / 4 / 5 | B / A / C / A+B | A / C / A / C | B直至stage5提交 |
| 6 / 7 / 8 / 9 | C / A / B / A+C | A / B / A / B | C直至stage9提交 |
| 10 / 11 / 12 / 13 | B / A / C / A+B | A / C / A / C | B直至stage13提交 |
| 14 / 15 / 16 | C视图 / C虚拟2× / A | 不写 / A / B | 无 |
| 17 / 18 / 19 | B视图 / B虚拟2× / A | 不写 / A / B | 无 |
| 20 / 21 | B / 已融合RGB结果 | O / 不再写 | 无 |

14/17只提交逻辑视图，不复制放大张量；15/18直接读取原始三行，由C5完成虚拟坐标映射。
21的signed8→uint8变换并入20的writer，等最后写响应成功后才提交20、21及整帧完成。

## 4. 错误与验证边界

loader检查读响应错误、提前/缺失last、保留位/非法参数命令；有未结束的读传输时
持续消费到last再返回错误。writer对失败写响应返回错误。错误完成不会发布成功帧。
收到错误后可重新START，全层参数/输入重装；结果valid保持到done_ready消费。

不支持在外部传输未结束时直接复位作为取消。DMA取消/排空、总线超时及CPU错误码
尚待系统整合；内存提供方若不再给last或写响应，当前核不会凭空宣称事务已结束。

回归：`golden/run_r2_graph_probe.py`、`sim/tb_c1_r2_microstyle_graph.sv`。
完整矩阵包括4×4、12×12（四分之一宽为奇数3）、32×32、640×12，每形状两幅不同图，
分别连续/背压；12×12另外覆盖八种读写错误及无复位恢复。十类非法几何/内存区域拒绝。
测试RAM为每字记录真实producer stage，拒绝未写数据、残差提前覆盖和写响应前跨层读取。
所有有效数值及padding逐128位字比对，expected数据只读不注入测试RAM。

首轮a所有4×4数据写回正确，但测试台在最终registered stage_done被计数前检查commits，
看到21而非22；仅修正TB采样顺序。b小矩阵通过；c强化为最终输出行写响应报错后禁止发布。
另外两个负例只破坏**实际RAM**的stage0写回数据/producer标记，stage1分别触发数值
不一致/错误来源检查，证明后层未使用golden替代输入。负例工具首轮参数选项放在源文件
之后而被Icarus当作文件名；仅修正命令格式，保留失败日志。当前源代码的两个负例均通过，
见`logs/r2_graph_handoff_negative_20260913_c.log`。

当前地址流水化源代码的完整矩阵（d小帧＋e原生宽度日志）已最终通过：8种配置、18个
正常帧、16个错误帧；正常输出共167,060个128位字、2,448,464个有效标量，包含全部
22节点逻辑提交。640×12两幅不同图连续模式均为549,624拍，背压分别592,499/591,501拍；
每帧实际读72,653字（特征70,320＋参数2,333）、写35,760字。均含装载/计算/写回，
但不是640×480或板级DDR帧率。流水修复比初版640×12增加594拍，即198份特征行描述符
各加三拍；数值、读写量与张量生存期均不变。

独立gate通过，并拒绝八种篡改/缺失日志证据；两个实际内存污染负例、可上传参数映像
逐项比较也通过。证据入口为`logs/r2_graph_evidence_gate_20260913.log`。

## 5. 物理时序的定位与修复

首轮`c1_ti60_r2_graph96_i3_20260913_a`综合/布局布线正常结束，但150MHz setup为
−0.469ns，不能把工具exit0当作时序通过。原摘要只保留关键词，缺少路径起终点；
为此给脱离式运行器补充**最多260行最终STA文本**，仍自动删除整个EDA数据库。
相同RTL的b重跑复现−0.469ns，路径为`active_stage[3]`→`rd_cmd_address[31]`。

根因是stage译码、行步长乘法、行坐标乘法和基址加法叠在同一寄存器路径。
现在层开始锁存行步长，每次特征行描述符增加坐标/base锁存、乘法、加法三拍，
不放宽6.666ns约束、不加假路径或多周期约束，不影响MAC或层内算术语义。

最终`c1_ti60_r2_graph96_i3_20260913_c`结果：

| 项目 | 初版C6 | 地址流水化C6 |
|---|---:|---:|
| XLR | 37,606 | 37,570/60,800（61.79%） |
| RAM | 144 | 144/256（56.25%） |
| DSP | 113 | 113/160（70.62%） |
| 最终setup/hold余量 | −0.469/+0.090ns | **+0.407/+0.089ns** |
| 核内最小周期 | 7.135ns | 6.259ns |

最终布局布线完成约266.7秒，核内估计Fmax159.770MHz；post-place hold负值在最终布线
后修复，最终hold为正。C5算子子层仍占128 RAM/108 DSP，新增writer为16 RAM/0 DSP，
图地址/计数路径另用5 DSP。未加入CPU、DDR PHY、视频、PLL与板级I/O约束。

物理摘要见`logs/efinity_resource_runs/c1_ti60_r2_graph96_i3_20260913_c/summary.json`；
按Efinity项目表的14个源文件执行Icarus `-DSYNTHESIS -tnull`结构编译，退出码0、
无诊断，见`logs/r2_graph_synthesis_compile_20260913.log`（空日志）。

## 6. 吞吐审计：当前装载口仍不满足15fps

`golden/r2_graph_traffic_budget.py`按真实拓扑、P2C8 padding和各行传输计数：

| 原生640×480项目 | 数值 |
|---|---:|
| 特征读取 | 2,812,800 × 16字节 |
| 参数读取 | 2,333 × 16字节 |
| 张量/最终帧写回 | 1,430,400 × 16字节 |
| 合计外部流量 | 67,928,528字节/帧 |
| 算子行周期之和（不含行间/图开销） | 6,116,160拍 |
| 32位装载口至少占用 | 11,255,866拍 |
| 不重叠架构的保守周期下界 | 18,802,426拍 |

因此即使忽略所有内存延迟、命令和控制开销，假定150MHz，当前实现上限也只有约
7.98fps，**不可能达到15fps**。这不是板测帧率，也不是从640×12线性拟合出的实测。
只增加AXI outstanding不能消除SRAM32位串行装载与三阶段不重叠；算子核已不是唯一瓶颈。

下一阶段必须推进128位片上装载写口、行缓存轮换/相邻行复用、load/compute/store重叠，
再把行描述符接入宽口burst DMA与多outstanding；不能靠放宽估算口径宣称达标。
上述150MHz只覆盖图核；native640×480完整回归和CPU/DDR/视频集成仍须单独取证。
