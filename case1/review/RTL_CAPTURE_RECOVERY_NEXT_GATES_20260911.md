# 捕获故障恢复：当前边界与下一项实现要求

日期：2026-09-11。此清单来自当前源码检查，不是新增功能已经实现。

当前已具备：RAW 坐标/标记校验、ISP 局部 flush、保留 SOF 的重同步、
正常采集及有 ISP 状态的取消排空停流检测。检测/超时选项默认关闭。
源恢复后的小尺寸整机 RAW 错误、缺失 EOF、正常采集超时均有 xsim/golden
证据；取消后停流新增前端测试，尚未做真实整机故障注入。

## 永久停止后强制恢复不能只加一个清零条件

`c1_async_stream_fifo.sv` 的 wr_rst/rd_rst 是各自时钟域的同步复位。
当前契约要求活动 FIFO flush 时两端一起复位；只复位一个指针会破坏
跨域占用关系。摄像头时钟若也停止，同步复位请求不会被它采样，不能凭
core 等待若干周期推定写侧已经复位。

因此未来强制恢复需要完整实现并验证以下契约：

1. 关闭新任务接纳，锁存一次恢复请求，保持现有物理区域记录。
2. 通过原取消路径排空已提交 AXI AR/R、AW/W/B；不得因本地复位撤销 VALID。
3. 明确由谁停止源、恢复 camera clock，以及提供源已经静止的确认；区分
   “没有 valid”与“没有时钟”。
4. 双域 FIFO flush 使用请求/确认握手；两域均真正采样复位后才允许释放，
   不用固定 core 延迟替代跨域确认。同步复位下时钟永不恢复就不能自动完成。
5. ISP pixel state 清理、配置/Gamma 保留，旧帧残留不可进入新帧；下一输入
   必须重新满足 SOF/x=0/y=0 接纳条件。
6. 只有 AXI 排空与跨域 flush 两种确认均满足，才能解除恢复 busy、释放记录
   并让软件重新 START。错误状态与“恢复完成”应分开定义。

接口尚未确定，不能把上述要求误解为当前已有 APB source-reset 命令或
板端传感器复位控制。实现前需核对现有寄存器映射、平台时钟/复位边界，
选择不会破坏默认接口的扩展；测试必须包含 camera clock 暂停、恢复，
以及复位请求与 AXI 最终 B 同拍。

## 本轮补充的参数门槛

常规 Icarus 回归新增两个预期失败配置：IDLE_TIMEOUT=-1，及
CHECK_RASTER=0/IDLE_TIMEOUT=16。要求非零退出码且精确诊断
`RAW idle timeout requires nonnegative cycles and raster checking`。
这些是仿真/配置阶段的保护，不是硬件运行时错误捕获；生产 initial
检查位于 `ifndef SYNTHESIS` 内。不要据此声称综合器会拒绝全部非法配置。

验证结果：全量 `run_iverilog_review_fixes.ps1` **547 配置通过**，退出码 0。
相对上一完整基线 541，包含取消排空停流 4 个新增配置与上述 2 个参数负测试。
本轮没有改生产 RTL，没有重跑整机 xsim，不延伸已有场景的覆盖结论。
