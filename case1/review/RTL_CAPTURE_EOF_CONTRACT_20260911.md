# EOF 缺失、错误标志与长暂停的边界

日期：2026-09-11。

## 必须区分的问题

1. 最后一个像素已到，但 EOF 为零；或 EOF 提前出现：属于光栅协议错误。当前 ISP 有仿真断言检查 EOF 与固定帧尺寸一致，但这不是可综合的硬件故障报告/恢复机制。
2. 帧中途没有新 token：在可暂停源契约下可能是合法长暂停，也可能是源断开。没有最大停顿时限或显式源故障信号，无法仅凭暂时空 FIFO 区分。
3. 已取消的帧还未送完 EOF：现有前端必须保留清理状态，不能按固定短超时释放后让残留帧尾进入新任务。

本轮没有新增任意固定超时、伪造 EOF 或放宽帧标志断言。

## 长暂停试验

新增 `RECOVERY_CASE=5`。发送真实 6×7 光栅，在第 20 个 token 被接受后暂停源，ISP 已进入 STREAM。上层请求 abort，保持 128 个核心周期，逐周期核验：

- cleanup_busy 持续为真；
- begin_ready 为假，不接受下一帧；
- 没有 ingress done、RGB 消费或错误；
- 相机接受计数仍为 20，证明暂停期间没有重复 token。

之后释放 abort，恢复源并送完同一帧剩余 22 个 token/EOF，等待实际流水线清理完成，再无复位发送两帧合法渐变图像，检查 40 个 RGB 像素及帧标志。

FIFO 16/32 × 相机半周期 3/7 ns 四组均通过。它证明有限暂停期间的保守等待与后续恢复，不证明无限时长暂停、独立域热复位或缺少 EOF 时的强制恢复。

## 标志错误试验

增加两个预期失败用例：完整帧不带 EOF，以及首个像素提前带 EOF。两者均明确触发 `R1 ISP EOF does not match frame dimensions`，不是仅以退出非零或超时作为通过。该检查位于仿真断言区域；真实硬件仍需后续可综合的输入完整性和重同步设计。

## 结果与后续方向

捕获定向 **34 配置通过**，含新增四个长暂停场景及两个错误 EOF 负测试。本轮未修改生产 RTL，未重跑全量；最近全量仍是 **458 配置**。

永久停流时不能将“等够时间”视为下游事务已经完成。后续恢复协议需要把源停止确认、相机/核心域 FIFO 协调复位、ISP 局部状态清理、DDR writer 事务排空和帧所有权释放分开定义；可能还需要显式丢弃至新 SOF 的重新同步路径。现有代码不能据本轮测试宣称已具备该功能。

本轮不运行 xsim、综合或板测，不生成波形；临时编译文件与向量由脚本清理。
